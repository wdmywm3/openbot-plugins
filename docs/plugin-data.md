# 插件持久数据

OpenBot 为每个实例里的每个插件提供独立的数据目录。数据库是目录中的可选存储能力；插件包更新不会覆盖运行数据。数据结构、迁移、查询与保留策略由各插件定义，宿主负责存储和权限边界。

| 插件 | 数据库与范围 | 保存内容 |
| --- | --- | --- |
| 每日签到 | `checkins`，聊天范围 | 按用户保存积分、日期、连续天数；排行与签到一起提交 |
| 骰娘 | `dice`，聊天范围 | 按用户保存角色卡，另存会话统计与默认骰式 |
| 内容监控 | `subscriptions`，实例范围 | 按订阅保存检查进度、基线、目标送达状态及待确认推送 |
| B 站 | `bilibili-history` | 实例内的 BV/分 P 资料与发送记录，以及聊天内的判断笔记 |
| bPhone | `phone-activities` | 公开或私人活动的独立进度、后续计划及途中笔记 |

群摘要只读取聊天内容，随机工具无需保存历史，表情包插件使用宿主已有的素材库；这三个插件没有需要另外迁移的数据。

## 旧记录如何迁移

每日签到、骰娘和内容监控会在访问相应记录时读取旧状态。新库已有记录时以新库为准；新库没有该记录时，才从旧状态继承。迁移不删除或改写旧数据。

签到优先继承较新的按用户记录，再兼容早期整群签到表；原有排行榜也会保留。新签到的积分和排行使用同一事务，发生版本冲突时重新读取，不重复增加积分。

角色卡仍按聊天和用户区分，群聊与私聊互相隔离。清空卡片、恢复默认骰式会在新库留下明确结果，之后不会重新导入旧值。统计和角色卡字段更新使用版本检查，避免同时写入时覆盖其他修改。

监控状态在下一次保存进度或人工确认推送时写入新库，单纯查看状态不会修改记录。已送达的目标与结果不明的目标均完整继承；结果不明的推送仍等待人工确认。不同订阅分别保存，互不覆盖。超过单条记录大小的大进度会分块，并将新分块、进度索引和旧分块清理一起提交；缺少分块时暂停检查，不重新建立基线。

缺少新数据库接口的旧宿主继续使用原状态接口。宿主已有数据库接口但读写失败时，会明确报错，不退回旧数据继续运行。旧数据是迁移保留副本；迁移后的变更只进入新库，不与旧版插件双向同步。

## 验证

插件仓库的 `npm test` 验证原功能及旧接口兼容性。配套宿主提供显式本地验证脚本：

```powershell
node scripts/verify-plugin-migrations.cjs <插件源码仓库目录>
```

该脚本使用真实插件 Worker 和 SQLite，覆盖旧记录保留、多人同时签到、排行事务、统计并发、角色卡隔离与清空、监控重启恢复、大进度及故障中止。QQ 和外部网络响应使用测试资料，不代表真实账号验收。

发布新包不会自动替换运行实例中的插件；用户在插件市场手动更新后才使用新代码。
