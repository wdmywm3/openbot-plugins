# 大肥鱼表情项目考察

参考项目：[dsh-nekowhale-stickers](https://github.com/Loping151/dsh-nekowhale-stickers)，核对的提交为 `b7b58c0ff347d639fabe87d90d6716c4b3cad185`。它包含表情知识库、检索与挑选、素材同步、本地模板制图、聊天接口，以及一个独立的网页桌宠；并非只有思考框模板。

## 可以借鉴的设计

- **先标注用法，再选表情。** [知识库格式](https://github.com/Loping151/dsh-nekowhale-stickers/blob/b7b58c0ff347d639fabe87d90d6716c4b3cad185/src/core/types.ts)分别保存画面文字、动作、情绪、场景、梗和双人动作方向。其[标注流程](https://github.com/Loping151/dsh-nekowhale-stickers/blob/b7b58c0ff347d639fabe87d90d6716c4b3cad185/tools/annotate/PROMPT.md)查看动图的时间序列；梗来源不确定时留空。OpenBot 已有图片文字、含义、标签、场景和不适合的情境，也能按时间采样动图。制作多人互动表情时，应继续把动作发起者、接受者和表达对象写进描述，避免反向使用。
- **相关候选允许变化。** 参考项目根据名称、标签、情绪和场景做加权匹配，并对接近的结果加入少量随机变化。OpenBot 保留已有语义检索与文字回退，在本次实现中按聊天记录近期成功发送的图片，仅对相近候选轻微降权；未发送成功不计入，精确搜图中文字时不改变排序。
- **填字模板有自己的输入约束。** 参考项目按模板列出文字或图片输入及建议长度；思考框使用短句，并在本地自动排版。OpenBot 本次支持在任意静态表情上设置相对文字区域、颜色、对齐和最大字号，中文短句均衡换行。模板内容由角色按当前聊天拟定，可以表达想法、玩梗或熟人间的轻松吐槽。
- **原图更新后留意旧标注。** 参考项目比较图片摘要与标注时的摘要，标记素材更新后的旧描述，并保留已经发出的旧图片。OpenBot 的角色包按图片内容保存资源，表情预置描述随对应图片一起分发；手工编辑的图库条目在角色包更新时保留。新增或替换图片时仍需检查描述是否对应实际画面。
- **用户选择具有优先权。** 参考项目允许 Agent 在用户配置范围内挑选；OpenBot 当前由用户设置单张发送开关、专属角色和聊天范围，角色只在允许范围内选用。现阶段不增加让角色修改用户配置的新工具。

## 其余功能与适用范围

参考项目支持按需或离线缓存素材、独立 CLI/MCP、回复标记、多人动作方向、举牌/对联/头像和逐帧 GIF 模板；它也有展示和余额查询用途的网页桌宠。OpenBot 已有自己的插件生命周期、媒体权限、QQ 图片投递和角色包更新流程。本次填字表情不依赖该项目的运行环境或网络服务；已有普通 GIF 表情继续使用，但 GIF 填字、图中嵌入头像和透视变形未纳入本版。

参考项目的源码、知识库和图片使用不同许可，知识库采用 CC BY-NC 4.0；原项目声明的图片素材也有独立使用条件。本次只参考设计思路，没有复制其知识库、表情图片或代码。嘻嘻新增图片使用本次生成的角色图，并为每张单独编写了描述。

## 表情查询怎样优化

目前一次查询先分页读取图库，按角色、聊天和启用状态过滤；随后结合候选中的语义匹配与关键词结果，再选择最多六张供角色查看。关键词索引覆盖图片文字、描述、含义、标签和情境；有角色专属加权，并对最近成功发送的图片轻微降权。语义接口本轮增加了 1.5 秒等待上限，超时或失败后继续使用关键词结果，不重复发起模型查询；随机选图不再计算关键词分数，关键词统计也减少了临时数组和重复判断。

当前主要成本有三处：每次查询都要读取和过滤全库；BM25 的查询词频统计会在当前候选上反复扫描；语义接口需要传入可用条目的 ID 和版本，底层也逐项计算匹配。另一个发送阶段的成本是检查范围时会重新遍历图库并发布图片引用。这些工作由后台服务或插件执行，但大图库仍会拉长当前聊天的等待时间。

建议按下面的顺序继续优化，先以实测确定瓶颈：

1. **测量完整链路。** 用不同规模图库分别记录冷启动、热查询、精确图片文字查询和语义查询的耗时；拆分读取、范围过滤、向量查询、排序与图片发布。配一组人工标注的聊天语境，检查前几张候选的贴切程度，并记录宿主事件循环延迟。
2. **减少每次全库读取。** 插件后台维护可重建的轻量检索快照或倒排索引，按图片变更、删除、角色和聊天范围更新；用户手动修改及权限变动立即使旧快照失效。查询只读取必要字段，返回候选前再次核对实际素材与当前授权。
3. **分路召回再合并。** 精确图片文字和名称走关键词索引，语义检索走共享检索接口，再在插件内合并和排序。可以评估宿主已有的通用混合索引，但不能只用关键词命中去裁掉语义候选，否则会漏掉没有同义词的相关表情。角色与聊天范围的正确过滤优先于任何性能优化。
4. **限制排序和发送成本。** 对召回结果做有界的前几名排序，保留按相关度优先、角色专属轻微加权及近期去重。发送前按实际图片 URL 找到关联条目并检查当前范围，避免每次重发整库的图片引用；旧记录和普通图片仍须保持兼容。
5. **覆盖退化与并发。** 测试模型冷启动、慢查询和锁等待时的超时回退；测试几万张表情、并发请求、取消和范围修改，不让一项慢任务占满执行资源。验证同一聊天近期去重、跨聊天隔离、禁用后旧图不可发送，以及关键词与语义召回率没有明显回退。

以上第 2–5 项是后续方案，本次没有声称已完成索引重构或大图库的查询基准。

## 本次验证范围

表情插件测试覆盖文本区域配置、合成、角色和聊天范围、旧结果撤销、成功发送后的近期记录及角色包元数据同步。真实模型是否会在不同群聊中自然选择填字表情，仍需在目标账号和模型上观察。
