# 收藏夹查询、排序与请求暂停

2026-10-26 完成实现。功能由 `bilibili-explorer` 插件负责，复用宿主现有状态、请求和操作记录接口，无须增加 B 站专用宿主接口。

## 查询方式

实测同一已收藏视频：网页收藏夹用标题关键词能返回对应条目，用完整 BV 号搜索返回空。因此 `search_favorites` 提供关键词查找，并明确空结果不能作为“未收藏”的依据。

收藏写入和恢复中的成员核对改用 `/x/v3/fav/resource/ids`。一次读取精简的编号和类型清单，再比较 AID 与视频类型。同一次任务复用已读清单；写入后失效，提交前后以及移除源收藏前的关键检查重新取得当前清单。不同账号和任务不共用缓存。接口明确返回不存在时才回退到原分页读取；风控、登录失败或响应格式不完整时停止，不换接口继续尝试。

精简清单可能包含已失效视频，因此不把它作为排序顺序。真实站点读取验证了默认收藏夹的 11 条编号和一个标题关键词命中；未进行线上收藏修改。

## 排序与恢复

`sort_favorites` 按 prepare、preview、apply 推进，status 可查看进度。支持反转、标题、时长、投稿时间、收藏时间和指定视频顺序；custom 将指定条目依次置前，其余维持相对顺序。每份清单最多 5000 条，资料缺失时不猜测时间或时长。

方案保存原始顺序、目标顺序和分页资料，预览返回绑定该方案的 token。执行时重新读取线上基线；内容或顺序变化则停止。通过最长递增子序列保留无需移动的条目，每批最多提交 100 次位置调整，不通过取消收藏来重排。每批写入前保存意图，之后读回核对，最后一批也确认后才标记完成。

超时或部分执行保留 pending，继续同一编号只核对结果，不重发原批。未解决的排序占用该收藏夹的排序记录，不能换新编号重复提交。排序与其他站内写入复用账号租约；多次调用之间保留原编号。核对中断超过两分钟后重读，持续分页则更新进度时间。

`undo(operationId)` 恢复本次排序前的顺序，包含已经确认的部分执行；仍需分批核对。线上后来增删或改过顺序时拒绝覆盖。正向 pending 先用原 apply 核对；撤销过程的 pending 继续原 undo。记录与撤销保留在已有操作记录入口。

## 持久暂停

站点级风控/限流与账号级登录失效分别保存在插件自身数据库的状态记录中，包含原因、时间、截止时间和本次暂停编号，不含登录凭据。

- HTTP 403/412、-352/-412：初次至少暂停 30 分钟；到期仍等待主人完成网页检查，调用 network_resume 核对登录后恢复。
- HTTP 429/503、-509/-799/-503/-504，以及宿主已报告的限流：初次暂停 5 分钟，连续发生延长等待，保留已取得的更长截止时间。
- -101 或身份检查返回未登录：暂停该账号，重新登录后检查恢复。

network_status 不联网。network_resume 仅限主人私聊，遵守截止时间，发起一次只读身份检查；用暂停编号比较更新，避免清除检查期间新增的暂停。恢复不会重发结果不明的写入。普通 API 与图片上传共用暂停规则；宿主既有通用请求队列继续生效。这些等待时间是插件策略，不代表平台承诺恢复。
