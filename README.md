# OpenBot Plugins

OpenBot 的独立插件仓库。插件列表由 `catalog.json` 提供，下载固定到 Git 提交，并逐文件校验 SHA-256。插件在 OpenBot 数据目录中安装，可以离线运行；配置与探索状态由各实例保存。

## 安装

在支持 GitHub 插件目录和后台 `runAgent` 的 OpenBot 中打开：实例配置 → 插件 → 插件市场。安装后添加到当前实例，设置配置并保存。权限或版本变化后，需要在实例中应用新版。

| 插件 | 功能 |
| --- | --- |
| `bilibili-explorer` | 按兴趣搜索、阅读、筛选视频，主动分享到绑定的 QQ 会话 |
| `content-monitor` | B 站 UP、直播及 RSS 内容监控 |
| `dice-maiden` | 骰娘、检定与角色卡 |
| `daily-checkin` | 签到 |
| `random-toolbox` | 随机工具 |
| `meme-library` | 表情素材 |
| `group-digest` | 群聊总结 |

## B站主动探索

先在 OpenBot 的目标群或私聊回复设置中开启“允许自主分享”。插件可填写指定会话（例如 `onebot:group:123456`）和探索兴趣；会话留空时让宿主选择已授权的目标。没有获准目标时不启动探索。默认每小时探索；分享冷却、每日上限和免打扰统一由本体管理。角色需要启用联网搜索和网页读取。旧插件配置中显式保存的限额、免打扰仍会额外限制探索，迁移时可清除这些旧字段。

默认使用 OpenBot 已有搜索工具。也可把“探索工具”改为角色已授权的 B 站 MCP 完整工具名称数组，选择搜索、视频信息、字幕等读取工具。插件不会安装 MCP 或保存 B 站 Cookie。任务沿用目标会话的模型与角色，每轮有工具次数和时间上限。

命令：`/explore` 立即探索，`/explorestatus` 查看状态，`/explorelike 主题`、`/exploreavoid 主题` 记录反馈；这些命令只允许实例主人使用。立即探索仍遵守免打扰、分享额度和去重。

探索结果可以为空。只有标题和简介时会要求模型说明阅读范围；候选链接必须出现在工具结果中才允许分享。推送前持久化候选，发送结果不明时不自动重发。重启后继续按已保存的时间运行，不补发积压任务。自主分享不自动 @ 群友；希望单独收到内容时，应为相应私聊开启分享。当前已发布的版本没有站内发言；下述管家测试版可另行开启评论和回复，不涉及私信。

## 开发与发布

插件入口为单个 JS 文件，导出 `handle(ctx)` 或 `poll(ctx)`，通过 `ctx.api` 使用宿主能力，不直接运行 Node/Python。`plugin.json` 声明权限、命令和配置。

`ctx.api.runAgent({taskId, chatId, prompt, tools, maxToolCalls, timeoutMs, maxActiveMs})` 返回 `{taskId, status, text, toolCalls, observedUrls, usage}`，不会自动投递。新版宿主按稳定 taskId 保存 Agent 检查点，自动压缩上下文；重试相同任务可恢复，已完成结果不会重跑。`ctx.api.getAgentTask({taskId, chatId})` 查询状态。`observedUrls` 是本任务工具返回的链接。宿主检查实例、会话、角色工具权限及插件启用状态。插件可用 `getState/setState` 保存实例状态，用 `push` 投递。按会话变化的数据应把会话 ID 纳入状态键；跨实例共享状态需要额外的 `state:global` 权限。

运行 `npm test`。修改插件时提升其版本，先提交插件文件，再运行 `npm run catalog` 生成指向该提交的目录，提交目录并推送。不要在目录里填分支名或未经校验的下载地址。插件代码的版本和权限变更都应在发布说明中写清。

现有六个插件从 OpenBot 项目迁移；主动探索为原生实现。实机模型与 QQ 推送验收仍需使用你自己的测试实例。

## B站管家 1.2.0（待在线验收）

沿用 `bilibili-explorer` 包 ID。需要支持持久化 Agent 的新版 OpenBot；新增 `network`、`secret` 权限。插件目录与发布目录仍分开管理，当前 `catalog.json` 未切换到本版本。

在实例插件设置填写大号／小号 UID，分别保存 Cookie。凭据由宿主加密保存，不作为普通配置或模型输入。`/biliaccounts main`、`/biliaccounts browse` 检查账号是否一致；账号失效或 UID 不符时停止，不自动切换账号。

收藏整理仅接受主人私聊命令：

1. `/bilifolders` 查看收藏夹编号，在设置中选择源收藏夹及目标分类规则。
2. `/biliscan` 分页扫描，每次最多 10 页，再次调用继续；`/biliscan new` 开始新扫描。
3. `/biliplan` 分批分类，每次最多 3 页，重复调用继续。资料与规则未变化的视频复用原分类结果。
4. `/bilipreview` 预览前 10 项，`/bilipreview 10` 查看下一页。
5. `/biliapply` 每次执行最多 5 项，重复调用继续。默认复制；选择移动时，确认目标存在后才移除源收藏。请求结果不明时先查远端，不重发。

也可配置主人私聊接收会话并开启自动整理，宿主轮询依次继续扫描、分类、应用方案，默认每天开始一轮。仅支持已有目标收藏夹；没有自动删除失效视频、自动新建收藏夹或撤销功能。

配置小号后，探索会读取小号推荐流，并按小号 UID 分别保存探索记录。仍只根据实际取得的标题、简介或工具内容说明推荐依据。选择“只生成草稿”后，`/bilidraft BV号 想表达的内容` 生成草稿，`/bilipost 草稿编号` 提交。选择自动模式后，再分别打开新视频评论、收到评论的自动回复，并填写评论管理私聊会话及发言要求。默认全部关闭。

自动评论针对探索选中的新视频；自动回复只处理启用后的“小号收到的回复”通知，首轮建立时间边界，不补回历史消息。每轮最多读取 3 页通知，分页进度和待处理队列持久化，队列满时暂停收取；不同时扫描全部评论区或回复任意 @。发送前读取原线程，确认对方确实回复本账号的评论；根评论与直接回复目标分别传递。读不到原文、没有实质内容时可以不发言。每个评论事件使用独立 Agent 任务，不导入 QQ 聊天记录。

手动评论与自动发言共用每天总额度，默认 3 条；自动发言默认相隔 10 分钟，同一线程最多回复 3 次，未处理任务超过 24 小时失效。规则修改后，旧规则下尚未完成的自动草稿会跳过。额度和动作在提交前保存；发送结果不明时绝不自动重发。接口接受后最多核对 3 次评论列表，读到只说明当前登录账号可见，不能保证所有访客可见。主人私聊 `/biliinteractions` 查询最近处理记录及问题。

同一 B站账号目前应只交由一个 OpenBot 实例自动操作。不同实例的凭据和记录隔离，尚未提供跨实例的同账号发言额度协调。

离线测试覆盖账号绑定、扫描／分类／执行、定时整理、通知分页、首次启用边界、楼中楼目标、发言额度、线程上限、原文失效、Agent 恢复及提交中断不重发。真实 B站接口、登录凭据与 QQ 投递仍需在测试账号上验收；`catalog.json` 保持原发布版本。

## 自主分享接口（1.2.0）

`share` 权限允许读取已开启分享的聊天 ID 和用户设置的偏好，以及调用 `api.proposeShare({content, url, chatId?})`。插件提供发现和真实来源；OpenBot 在目标聊天的独立上下文中判断相关性、隐私与打扰程度，决定是否发送并生成文案。返回拒绝不改用 `push`，未知发送不自动重试。旧宿主没有接口时停止分享并提示更新。

探索兴趣、来源采集、候选筛选和探索预算属于插件；接收许可、频率、聊天上下文、最终发送和去重属于本体。`push` 仍仅用于原有收藏整理结果通知。截图分享由安卓宿主控制，B 站插件不能通过此接口上传任意文件或桌面截图。奖励学习尚未实现。

目录仍指向已发布版本；本分支的新版需要与支持自主分享的宿主完成真实模型和 QQ 测试后，再更新目录。
