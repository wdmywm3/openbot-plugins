# OpenBot Plugins

OpenBot 的独立插件仓库。插件列表由 `catalog.json` 提供，下载固定到 Git 提交，并逐文件校验 SHA-256。插件在 OpenBot 数据目录中安装，可以离线运行；配置与探索状态由各实例保存。

## 安装

在新版 OpenBot 侧边栏打开“插件市场”，安装并确认授权后进入详情，点击“管理”，选择实例并保存参数，再到实例或会话的“插件”页开启。插件包共享安装，账号、参数和状态按实例隔离。权限、Hook、界面与动作声明或包内容变化后需要重新授权；普通配置保存保留授权。实例与会话的启用开关单独保存。旧版宿主的市场入口位于实例配置 → 插件。

| 插件 | 版本 | 功能 |
| --- | --- | --- |
| B站小管家（`bilibili-explorer`） | 1.9.0 | 浏览、笔记、点赞、收藏、评论、QQ 分享与收藏夹整理 |
| bPhone（`android-roamer`） | 2.2.0 | 按目标使用已绑定的安卓设备，保存活动进度 |
| `content-monitor` | 1.0.1 | B 站 UP、直播及 RSS 内容监控 |
| `dice-maiden` | 1.3.1 | 骰娘、检定与角色卡 |
| `daily-checkin` | 1.0.1 | 签到 |
| `random-toolbox` | 1.0.1 | 随机工具 |
| `meme-library` | 1.0.1 | 表情素材 |
| `group-digest` | 1.0.1 | 群聊总结 |
| `watch` | 0.4.0 | 结合画面和字幕理解视频，按时间戳补看；[安装与使用](plugins/watch/README.md) |

Watch 0.4.0 是独立的 Skill + 工具插件，复用宿主通用接口。默认优先获取 1080p 视频并读取完整画面，细节不清时可从原视频局部裁剪补看。回归及宿主 MCP 图片转发验证通过；2026-10-25 已实际验证 B 站下载、高清抽帧、中文转写及英文语音时间偏移。YouTube 的真实下载仍需相应登录条件。详情见[安装与使用](plugins/watch/README.md)。

更新由用户在插件市场手动执行。插件代码安装在独立版本目录，配置、状态、数据库和 MCP 数据保存在数据目录中，不随插件包替换。数据结构变化由插件迁移，并保留旧记录；详见[插件持久数据](docs/plugin-data.md)。

## B站小管家

当前版本为 1.9.0。原“逛 B站”和收藏管理功能使用同一个包、账号配置和数据目录；显示名称统一为“B站小管家”。视频补读默认接入独立的 Watch，旧媒体绑定及备份设置继续沿用。两者均可从插件市场安装，也可通过各自的 `plugin.json` 导入。配置和恢复流程见 [MEDIA.md](plugins/bilibili-explorer/MEDIA.md)。

先在 OpenBot 的目标群或私聊回复设置中开启“允许自主分享”。插件可填写指定会话（例如 `onebot:group:123456`）和探索兴趣；会话留空时让宿主选择已授权的目标。没有获准目标时不启动探索。默认每小时探索；分享冷却、每日上限和免打扰统一由本体管理。角色需要启用联网搜索和网页读取。旧插件配置中显式保存的限额、免打扰仍会额外限制探索，迁移时可清除这些旧字段。

默认使用 OpenBot 已有搜索工具。也可把“探索工具”改为角色已授权的 B 站 MCP 完整工具名称数组，选择搜索、视频信息、字幕等读取工具。插件不会安装 MCP 或保存 B 站 Cookie。任务默认继承实例模型，也可以在市场中按实例、插件选择后台任务模型；沿用目标会话的角色，每轮有工具次数和时间上限。

命令：`/explore` 立即探索，`/explorestatus` 查看状态，`/explorelike 主题`、`/exploreavoid 主题` 记录反馈；这些命令只允许实例主人使用。立即探索仍遵守免打扰、分享额度和去重。

探索结果可以为空。只有标题和简介时会要求模型说明阅读范围；候选链接必须出现在工具结果中才允许分享。推送前持久化候选，发送结果不明时不自动重发。重启后继续按已保存的时间运行，不补发积压任务。自主分享不自动 @ 群友；希望单独收到内容时，应为相应私聊开启分享。站内评论、回复和私信默认关闭，可按账号及目标分别启用；详见[阅读与互动](docs/bilibili-social-and-reading.md)。

## 开发与发布

插件包可包含多个 Skill、references、MCP 定义和 JS 工具/Hook。新版采用 Agent Plugins 的 plugin.json，OpenBot 声明放在 extensions.com.openbot；旧格式继续兼容。不携带二进制文件。JS 部分导出 `handle(ctx)` 或 `poll(ctx)`，通过 `ctx.api` 使用宿主能力，不直接运行 Node/Python。`plugin.json` 声明权限、命令和配置。

本地开发版本已使用通用界面声明，发布目录尚未更新。插件在 `extensions.com.openbot` 中声明 `ui: {version:1, sections:[{id,title,fields,widgets}]}`，分栏按 `configSchema` 字段生成。无须在宿主新增按插件 ID 判断的组件。数组可用 `ui.widget: "collection"` 和 `ui.itemLabel` 显示条目列表；枚举数组可用 `"choices"`；长文本使用 `"multiline"`。`"tools"`、`"media-services"` 复用工具与媒体绑定控件，媒体字段名由插件决定。字段的 `ui.advanced: true` 收入“更多设置”，`ui.when: {field, equals}` 控制显示条件，隐藏时保留值。

`widgets` 可声明加密凭据 `secret`、浏览器账号 `browser-account` 和管理按钮 `action`。账号的登录网址、配置字段和登录结果 JSON 路径由插件提供，宿主统一处理实例/插件/账号隔离。需要自定义账号检查时引用只读 native 动作，返回 `{identity,label}`。示例见 [B站声明](plugins/bilibili-explorer/plugin.json)；订阅列表与立即检查见 [监控声明](plugins/content-monitor/plugin.json)。

`actions` 的 `native` 动作提供 `id/title/export/inputSchema/readOnly/resultTemplate`，通过现有 worker 执行，来源身份为 `desktop`，不会伪造主人私聊。普通管理动作不能发 QQ 消息、启动 Agent 或创建定时任务；只读动作还禁止写状态及 POST。`kind: "background"` 复用已声明的 `background.export` 与后台互斥；同类聊天命令用 `execution: "background"` 共享互斥。普通管理按钮接收 `{}`，设备设置中的按钮接收 `{deviceId}`，账号检查接收 `{profile}`，动作输出限制为 64 KiB。

[bPhone 声明](plugins/android-roamer/plugin.json) 使用 `ui.layout: "resource-manager"`、`resourceType: "android"` 和 `resources`。资源的 `settingsFields` 从本插件 schema 选字段；`policy` 的 `enabledField`、`allowedAppsField`、`unrestrictedAppsField` 分别映射按需使用开关、允许应用列表和不限应用开关。`activity` 可声明公开网页范围；bPhone 不再限定为 B 站视频。`autonomy` 映射闲时运行的开关与时间字段。设备设置按插件 ID 隔离；连接、物理归属与同设备串行由宿主负责。新增字段或更换插件 ID 不需要修改宿主。新宿主不再补旧插件声明、读取旧设备业务字段或在启动时搬运旧内置包。

Bot 配置继续使用已有 `workspace` 读、写、编辑，在主人私聊中按需读取 `plugins/index.json`，再读取相应插件的配置和 schema；设备配置使用 `plugins/<id>/resources/android/<device-id>.json`。不会为界面声明增加模型工具或把整份 schema 常驻塞进上下文。配置写入有字段校验、版本冲突检查和实际生效处理，凭据不回传模型。

外部资料通过现有 `runAgent` 的 `externalContent: [{source, content}]` 单独传入，`prompt` 只放任务目标和已授权规则。宿主将文本、截图和衍生摘要包裹为 `external_content`，转义伪造标签，并在系统协议中禁止执行资料夹带的要求。最多 16 项资料，来源名最多 128 字符，序列化内容合计最多 64,000 字符；超出时分段读取。bPhone 的活动进度及 B 站的标题、评论、字幕、分类与评估资料已按此分离，没有增加模型工具。

`ctx.api.runAgent({taskId, chatId, prompt, tools, maxToolCalls, timeoutMs, maxActiveMs, resource?})` 返回 `{taskId, status, text, toolCalls, observedUrls, usage}`，不会自动投递。新版宿主按稳定 taskId 保存 Agent 检查点，自动压缩上下文；重试相同任务可恢复，已完成结果不会重跑。`ctx.api.getAgentTask({taskId, chatId})` 查询状态。`observedUrls` 是本任务工具返回的链接。宿主检查实例、会话、角色工具权限及插件启用状态。插件可用 `getState/setState` 保存状态，用 `proposeShare` 提议自主分享，订阅及任务通知使用独立的 `push` 权限。状态默认按聊天隔离；选择 `channel` 范围存放多聊天数据时，键中应包含聊天 ID；跨实例共享状态需要额外的 `state:global` 权限。

运行 `npm test`。修改插件时提升其版本，先提交插件文件，再运行 `npm run catalog` 生成指向该提交的目录，提交目录并推送。不要在目录里填分支名或未经校验的下载地址。插件代码的版本和权限变更都应在发布说明中写清。

现有六个插件从 OpenBot 项目迁移；主动探索为原生实现。实机模型与 QQ 推送验收仍需使用你自己的测试实例。

## B站小管家：账号与收藏管理

沿用 `bilibili-explorer` 包 ID。需要支持持久化 Agent 的新版 OpenBot；新增 `network`、`secret` 权限。以下保留账号与收藏管理功能的版本演进说明；当前包的权限以安装时显示的清单为准。

在插件市场中选择实例。1.4.0 增加“内置浏览器”登录方式：分别打开大号和小号窗口登录，点击“检查登录”识别 UID，再保存配置。登录状态保存在 OpenBot 数据目录，关闭浏览窗口后仍可后台读取，重启后继续使用；网站使登录失效时需要重新登录。升级旧绑定后可选择这项方式，也可以保留“手动填写 Cookie”。Cookie 方式的凭据由宿主加密保存，不作为普通配置或模型输入。`/biliaccounts main`、`/biliaccounts browse` 检查账号是否一致；账号失效或 UID 不符时停止，不自动切换账号。

内置浏览器需要新版 OpenBot 和插件的 `browser` 权限；整理收藏、发送评论等 POST 请求还需要 `browser:write` 权限，具体操作仍受管家原有设置约束。大号、小号以及不同实例的浏览器数据隔离。宿主负责保存登录、执行请求、排队和随机间隔，插件负责 B站业务；插件不会取得浏览器 Cookie。

收藏整理仅接受主人私聊命令：

1. `/bilifolders` 查看收藏夹编号，在设置中选择源收藏夹及目标分类规则。
2. `/biliscan` 分页扫描，每次最多 10 页，再次调用继续；`/biliscan new` 开始新扫描。
3. `/biliplan` 分批分类，每次最多 3 页，重复调用继续。资料与规则未变化的视频复用原分类结果。
4. `/bilipreview` 预览前 10 项，`/bilipreview 10` 查看下一页。
5. `/biliapply` 每次执行最多 5 项，重复调用继续。默认复制；选择移动时，确认目标存在后才移除源收藏。请求结果不明时先查远端，不重发。

1.4.1 按 BV 号保存视频记录，包括 AV 号、标题、简介、最近扫描时间、分类结果和分析时间；收藏夹关系另行保存。移动收藏夹、在多个收藏夹中重复出现、重启后重新扫描均复用已完成的分类。标题、简介、标签、可用内容摘要或分类规则变化时才重新分类；旧版分类缓存会自动沿用。资料不足的结果标记为待确认，不执行整理。每个成功批次单独保存，中途失败后继续，不重跑已保存的批次。记录按实例和 B站账号隔离；字幕、音频、画面分析仍按聊天和分P分别保存。

1.4.2 配合新版宿主，在插件市场选中实例后可查看“运行记录”，按视频号或状态筛选扫描、分类、复用、待确认及执行结果，保留最近500条。视频分类记录不受这个日志条数限制。插件随包提供 `SKILL.md`，由宿主加载到管家发起的 Agent 任务中；只分类测试方案带有执行限制，不能通过 `/biliapply` 修改收藏。

`npm test` 包含移动、复制、重启、旧记录迁移及中断恢复测试。另可运行 `node tests/video-ledger-storage.cjs OpenBot源码目录`，使用宿主实际 SQLite 存储验证跨进程恢复和实例隔离；该测试创建临时数据库，不读取真实账号，也不修改 B站收藏。

也可配置主人私聊接收会话并开启自动整理，宿主轮询依次继续扫描、分类、应用方案，默认每天开始一轮。操作结果不明时先核对远端；恢复和撤销流程见 [MEDIA.md](plugins/bilibili-explorer/MEDIA.md)。

配置小号后，探索会读取小号推荐流，并按小号 UID 分别保存探索记录。仍只根据实际取得的标题、简介或工具内容说明推荐依据。选择“只生成草稿”后，`/bilidraft BV号 想表达的内容` 生成草稿，`/bilipost 草稿编号` 提交。选择自动模式后，再分别打开新视频评论、收到评论的自动回复，并填写评论管理私聊会话及发言要求。默认全部关闭。

自动评论针对探索选中的新视频；自动回复只处理启用后的“小号收到的回复”通知，首轮建立时间边界，不补回历史消息。每轮最多读取 3 页通知，分页进度和待处理队列持久化，队列满时暂停收取；不同时扫描全部评论区或回复任意 @。发送前读取原线程，确认对方确实回复本账号的评论；根评论与直接回复目标分别传递。读不到原文、没有实质内容时可以不发言。每个评论事件使用独立 Agent 任务，不导入 QQ 聊天记录。

手动评论与自动发言共用每天总额度，默认 3 条；自动发言默认相隔 10 分钟，同一线程最多回复 3 次，未处理任务超过 24 小时失效。规则修改后，旧规则下尚未完成的自动草稿会跳过。额度和动作在提交前保存；发送结果不明时绝不自动重发。接口接受后最多核对 3 次评论列表，读到只说明当前登录账号可见，不能保证所有访客可见。主人私聊 `/biliinteractions` 查询最近处理记录及问题。

同一 B站账号目前应只交由一个 OpenBot 实例自动操作。不同实例的凭据和记录隔离，尚未提供跨实例的同账号发言额度协调。

离线测试覆盖账号绑定、扫描／分类／执行、定时整理、通知分页、首次启用边界、楼中楼目标、发言额度、线程上限、原文失效、Agent 恢复及提交中断不重发。真实 B站接口、登录凭据与 QQ 投递需结合使用者的测试账号验收。

## 自主分享接口（1.2.0）

`share` 权限允许读取已开启分享的聊天 ID 和用户设置的偏好，以及调用 `api.proposeShare({content, url, chatId?})`。插件提供发现和真实来源；OpenBot 在目标聊天的独立上下文中判断相关性、隐私与打扰程度，决定是否发送并生成文案。返回拒绝不改用 `push`，未知发送不自动重试。旧宿主没有接口时停止分享并提示更新。

探索兴趣、来源采集、候选筛选和探索预算属于插件；接收许可、频率、聊天上下文、最终发送和去重属于本体。`push` 仍仅用于原有收藏整理结果通知。截图分享由安卓宿主控制，B 站插件不能通过此接口上传任意文件或桌面截图。奖励学习尚未实现。

自主分享需要支持相应接口的宿主；首次启用时应在测试聊天验证模型和 QQ 投递。

## bPhone 2.2.0

bPhone 是 Bot Phone，包标识为 `android-roamer`。安装批准、绑定设备并在实例启用后，Bot 可以为当前目标按需使用自己的手机，包括查资料、游戏、体验应用和继续上次活动。群聊和私聊都可获得插件提供的设备认知；群友不会因此获得主人私人任务或设备配置权限。

2.2.0 增加有来源、可修订和撤回的经验检索，以及闲时从已有活动和待解决问题中选择下一步。B站小管家 1.8.0 同时加入实际字幕区间、按问题补读、独立点赞/收藏/评论/分享、评论 @ 通知和连续私信合并；设计与验证见[阅读、互动与经验记录](docs/bilibili-social-and-reading.md)。版本信息以市场目录为准。

插件设置先展示设备卡片，每台设备绑定一个实例，一个实例可有多台。进入卡片管理连接与使用设置，不用下拉菜单切换设备。连接支持本机或局域网 ADB 地址、端口扫描和截图确认；保存连接不会开启闲时活动。物理设备的唯一归属、队列、待机和恢复由宿主管理。

“按需使用手机”默认开启，“闲时自行活动”默认关闭，两者独立。默认允许手机上的应用；如需限制，在“更多设置”关闭不限应用并填写包名。主人仍可在自己的私聊交办明确任务；普通按需使用和私人任务使用当前聊天的角色、主模型，闲时活动使用独立上下文和所选后台模型。

角色需要启用 `channelPlugin` 和 `useSkill`。插件 Skill 与只读 `context` hook 说明手机用途、选择方法和工具：`use` 按目标使用，`status` 查询公开活动或分页列设备，`resume` 由主人继续中断任务。私人任务通过 `use/status/resume` 的 `private:true` 访问，仅限主人的当前私聊。提醒不含连接地址、私人任务或实时画面；停用和卸载不会改写旧提醒，也不追加失效提醒。

私聊命令 `/phone [--device 设备] 目标`、`/phonestatus`、`/phoneresume` 分别交办、查询和继续本私聊的私人任务；`/roam [--device 设备] [兴趣]` 开始 Bot 自己的活动。设备未指定时优先默认或唯一设备，多台无默认时询问。主人任务可优先打断公开活动，完成后恢复。

每台设备保存目标、实际进度、下次打算、协助需求和最近尝试，后续活动按摘要接续并重新观察屏幕。私人进度保存在原私聊，不会混进公开活动。“查看近况”通过通用管理动作显示公开记录。正常游戏推进、解决问题或觉得有趣均可算有收获，不要求产出可分享链接。

闲时活动每分钟检查机会，未抽中不调用模型。默认空闲后休息 10 分钟，随后平均等待 30 分钟，每天最多启动 6 次。连续低收益才将等待延长为 2 倍、最多 4 倍，错误及分享结果不充当收益评分。设备忙、主人任务、手动待机或执行结果不明时不启动；重启或改变设置后先休息，不补跑。

普通登录页先判断现有账号流程或改做其他活动；确实缺少凭据、验证码或人工验证时保存需求并让出设备。可通过应用商店界面获取明确免费的应用；没有新增 APK 安装接口。任务提示继续禁止付款、订阅、转账、修改安全设置和替他人发消息。公开分享仍须经过目标聊天审核，私人任务不分享画面或内容。

接口复用 `runAgent`、`getState/setState`、CAS 和 `proposeShare`。按需任务使用 `mode:"self"`、`resource:android:self` 和显式启用策略；私人任务使用 `mode:"private"`，后台使用 `mode:"explore"`、`resource:android:autonomous` 和 `considerAutonomy` 的一次性机会。宿主签发本次设备能力、检查授权并排队，插件不操作 ADB 进程或锁。

插件需要配套新版宿主，新权限和包内容需重新批准。发布到目录后仍由用户手动安装或更新，不替换正在使用的版本。

任务返回临时 `resultId`、`hasScreenshot`；插件用 `proposeShare({resultId,content,includeScreenshot})` 提交发现。截图由宿主持有，凭据只在本次执行内有效，最长 5 分钟。`getShareTargets({resultId})` 可查询该结果允许考虑的目标。未获准、旧宿主或分享失败均不降级为直接发送。已完成任务不重截当前屏幕、不重发旧发现。

离线测试覆盖按需活动、群聊提醒、私人隔离、跨轮进度、CAS 准入、结果凭据、恢复、设置变化和闲时退避。宿主另测真实包的导入、批准、worker、设备能力及卸载撤权。设备、真实模型和 QQ 分享应在各自测试环境联合验收；尚未实现奖励学习系统。

### 1.4.3 分类与后台模型

后台任务默认继承实例模型；在插件市场选择实例后，可为插件选择其他已配置模型。宿主统一提供模型列表、保存模型 ID 并读取完整模型参数和凭据，插件不另设输出额度或温度。分类按输入资料长度分批，优先依据视频重点归入一个较宽的分类，也允许多个确有必要的目标。移动到多个目标时，全部确认加入后才移除源收藏；只分类测试方案不能执行移动。

## 多组件插件

B站小管家和 bPhone 已采用统一包结构，并提供 channelPlugin Agent 工具。安装后在实例中启用插件，角色启用 channelPlugin 和 useSkill；自然语言任务先加载相关 Skill，再发现并调用结构化工具。命令仍可作为兜底。B站扫描工具默认只分类；需要整理时显式创建 previewOnly=false 的扫描并检查方案。两种模式不会混用旧方案。

Skill 随插件安装、更新、卸载，不复制到用户技能库。管家的私密工具限主人私聊，bPhone 的按需使用可用于群聊；插件权限仍由宿主检查。市场目录固定到完整 Git 提交，下载时逐文件核对内容哈希。
