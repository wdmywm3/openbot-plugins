# Imagegen · 画图

本 Skill 从 Codex 的 imagegen 工作流改写为 OpenBot 画图插件用法。执行入口只有 `draw_image`；插件负责选择已配置的服务、读取参考图、保存结果。不要调用本机命令、其他应用的文件或当前 Codex 会话的 `image_gen` 工具。

## 先判断任务

1. 用户想新画一张图时，使用 `mode:"image"`。用户提供图片只作为主体、风格、构图或氛围参考时，仍是普通生图，传 `references`。
2. 用户想改一张已有图片时，使用 `mode:"image"` 并传原图的 `references`；提示词明确“只改什么、保留什么”。参考图不可读时停止并说明原因，不改成纯文字生图。
3. 用户要你画自己的形象、自拍、近照或穿搭时，使用 `mode:"selfie"`。插件优先读取当前角色的人设图，缺少时使用“自拍形象”里的备用图。明确要求侧面、背面、Q 版或细节时，分别填 `selfieView:"side"`、`"back"`、`"chibi"` 或 `"detail"`，其余情况留空。调用时无需填图的路径，也不要传聊天参考图。自拍是绘图结果。
4. 普通生图与自拍分别开关。方式关闭时说明对应设置。缺少人设图时提示在角色中添加图片，或在“自拍形象”里上传备用图。
5. 工具返回仅主人可用时，告知请求者当前的画图权限。

## 准备提示词

保留用户的主体、风格、画幅、文字和禁忌。请求很具体时只整理成清晰说明；请求很宽泛时才补有帮助的场景、构图与光线。不要凭空增加角色、品牌、对白、道具或剧情。

复杂任务可采用以下顺序，不必每次填满：

```text
用途：图片将用在哪里
主要要求：用户要求的主体与动作
参考图：图1是主体/编辑目标；图2是风格/构图参考
场景与构图：视角、景别、背景与留白
风格与光线：写实、插画、产品图等
画面文字：逐字写出；不添加其他可读文字
约束：必须保留的身份、服装、比例、物体、布局
```

参考图按工具传入顺序从图1编号，并在提示词里说明每张图的作用。用户要求保持角色、脸、布局或原图其他部分时，每次改图都重述这些约束。自拍固定形象应保持同一角色的脸、发型与核心辨识特征，只改变用户指定的场景、表情、姿势或穿搭。

详细提示词原则见 `references/prompting.md`，相关场景的可改写范例见 `references/sample-prompts.md`。只在需要时通过 `useSkill(resource="references/...", ...)` 读取，不要把范例中的设定当成用户要求。

## 调用 draw_image

每次调用生成一张图片。多张不同内容要分别写提示词、分别调用；同一个请求继续查询原任务，不重新提交。工具参数：

```json
{
  "mode": "image",
  "prompt": "完整画面要求",
  "size": "1024x1024",
  "quality": "medium",
  "format": "png",
  "references": [{ "messageId": "真实消息编号", "index": 0 }]
}
```

省略 `provider` 即沿用插件设置；自动服务优先使用当前聊天已配置的 Codex 登录。只有用户明确选择供应商时才传 `provider`。不要为失败的 Codex 任务自行改用 API Key 服务，也不要自动重试可能产生费用的请求。

`references` 只接受实际可访问的聊天图片消息编号或已返回的 `assetRef`，最多两张。不要猜测编号、伪造 Base64 或把网页图当成聊天附件。自拍不传 `references`。尺寸仅支持 `auto`、`1024x1024`、`1536x1024`、`1024x1536`；画质为 `auto`、`low`、`medium`、`high`。`background:"transparent"` 需选用支持透明输出的服务，并搭配 PNG 或 WebP；服务拒绝时说明原因，不悄悄改成不透明图片。各服务差异见 `references/provider-controls.md`。

用户要 GIF 动图时传 `format:"gif"`，提示词写清主体、动作及是否循环；如用户指定帧数或每帧时长，可传 `frameCount`（2–16）和 `frameDurationMs`（20–2000 毫秒）。未指定尺寸时使用自动尺寸。插件通过所选服务请求支持动图的模型；若账号或服务拒绝，说明当前服务不可用，不自动切换到其他计费服务。自拍动图同样沿用固定形象和自拍开关。

工具以 `action:"start"`、`input` 和稳定 `requestKey` 启动；`running` 时以原 `jobId` 查询 `action:"status"`，取消以 `action:"cancel"` 执行。`phase:"queued"` 表示正在排队，可以告知用户并继续查询原任务，不要重复提交。失败、超时或取消后先核对原任务，不自动再次扣费。

## 核对与交付

只有 `completed.result.images` 才代表生成成功。查看生成图是否符合主体、构图、文字、参考图身份与用户的硬性要求；若不符，说明具体差异，再按用户意愿进行一次有针对性的改图。发送时使用 `images[].url`，后续普通改图使用 `images[].assetRef`。没有图片结果时不要声称已经出图。
