# 画图

调用 `draw_image` 时，外层 `title` 是聊天里显示的任务名，`input.prompt` 是单独发给图像模型的正文。构思时可以读聊天记录；提交前单独读一遍正文，想象接收方只看得到这段话和实际附上的图片。以画面中看得到的主体、场景或编辑指令起笔。收件人、群昵称、任务来由、聊天分析、文件路径和调用步骤留在聊天里。若名字指明用户要画的具体角色，保留角色名和必要的辨识特征；若昵称是要求印在画上的字，逐字写出并交代位置。

例如群友“小叶”要一张雨夜修伞匠的头像，任务名可叫「小叶的修伞匠头像」。实际提交的 `prompt` 可以是：

> 水彩头像。年轻修伞匠低头托着半开的深蓝布伞，拇指按住一根松脱的伞骨。平视胸像，脸和指尖落在画面中央，伞沿在头顶留一道弧线。她盯着扣上的铆钉，一边嘴角刚刚扬起。窗外的冷蓝雨光勾出伞沿，桌灯在指尖和铜钉上留下两点暖光，后面的工具架化成浅色块。

## 从需求写成画面

用户给了定稿并要求原样使用时，直接采用那段正文。用户只要提示词时，把写好的正文交给对方；需要成图时再提交生成。

1. **确定这一张要解决什么。** 新图先抓主体、媒介和一个可见瞬间。头像要在小尺寸下读得清脸和轮廓，环境图要读得出空间，产品图要看清外形与表面，海报要为文字留位置。聊天中的印象转成可见的造型、动作或物件；由你联想的服装与场景是创作选择，不把它说成对方的真实长相。
2. **摆好构图再写细节。** 选景别、机位和取景边界；明确主体占幅、朝向、视线落点、前后遮挡和留白。动作有关键接触点时，让握住的手、被握的物件和脸在这个机位同时可见。多人画面用位置、服装轮廓或各自拿的物件区分人物。
3. **让光线解释画面。** 找到主光从哪里来、落在哪里，背光侧与背景怎样分开。按场景补软硬、冷暖或反射。材质落实到受光表现，例如搪瓷杯沿的一线硬反光、羊毛袖口宽而柔的暗面。
4. **把情绪落在动作上。** 在看得清脸的景别里，选一两个相互配合的信号，如视线仍停在门把手上、下眼睑微收、抿住的嘴角刚松开。远景用头肩姿态、重心、人与人之间的距离。静帧选定情绪的一个瞬间，动图才描述动作如何变化。
5. **给细节分配轻重。** 焦点附近留少量可信的纹理或结构，背景随距离简化。以用户指定的年龄、身份、服装、色彩和媒介为准。检查光向、动作、裁切、文字与参考是否能同时成立。

这些是构思维度。正文写成连贯的自然语言，长短由画面决定。简单改色一句就够，复杂海报则应写全准确文案、位置和层级。尺寸、格式、画质用工具字段；额外道具、通用负面词、质量口号和逐项检查表都不作固定结尾。

## 参考图和编辑

- **新构图**按实际传入顺序称图1、图2，直接描述关系，例如“图1中的人坐到图2的窗边，手肘压在窗台上，沿用窗外向左落下的影子”。每次独立调用都带上本张所需的参考。
- **局部编辑**点清原图、位置、改变和保留范围。例如“将图1右侧人物手里的黑伞换成透明伞，保留手指握法、面部和原有街灯倒影。”参考图不可读时说明缺失。
- **固定角色自拍**用 `mode:"selfie"`。用户要角色模仿某张图时，把该图放进 `references`。静态图和动图均可传最多四张，按传入顺序在提示词里写清用途，例如“模仿图1睁圆双眼、张嘴惊叫的表情，采用图2的近景构图”。多帧 GIF 和 WebP 会自动附上动作拼图，角色形象图也会一并提供。需要交错使用底图、动作和角色图时，可用 `referenceOrder` 自定顺序，并在提示词里引用最终图号。只有明确要求特定视角时才传 `selfieView`。
- 需要更细的光影、微表情、材质或风格决策时读 `references/prompting.md`；想对照海报、场景、合成、自拍等成稿时读 `references/sample-prompts.md`。示例中的具体设定只属于该例。

## 提交和使用结果

用 `draw_image` 的 `action:"start"` 提交；外层填写简短的 `title` 和稳定的 `requestKey`，`input` 中放 `mode`、创作正文 `prompt` 及本张所需的参数。一次生成一张，本轮有多条请求时分别关联真实的 `messageId`。同一条消息的多张参考使用相同的 `messageId`，按附件顺序填写从 0 起的 `index`。同一请求重试沿用原 key。

只在用户要聊天反应表情时使用 `purpose:"sticker"`，草稿另加 `draft:true`。普通图片与动图默认使用 `purpose:"image"`。动图写清动作起止、固定机位或循环方式，使用 `format:"gif"` 及所需的帧参数。

提交后等待原任务回执。生成成功时，按原请求用 `images[].url` 交付、暂存或继续改图。查询、取回旧图、取消及工具字段详见 `references/tool-use.md`；选择服务和模型时再读 `references/provider-controls.md`。
