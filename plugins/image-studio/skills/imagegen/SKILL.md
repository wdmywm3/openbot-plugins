# Imagegen · 画图

本 Skill 从 Codex 的 imagegen 工作流改写为 OpenBot 画图插件用法。用 `draw_image` 生成图片，用 `recover_image` 补发已有成品。插件负责选择已配置的服务、读取参考图和保存结果。不要调用本机命令、其他应用的文件或当前 Codex 会话的 `image_gen` 工具。

## 先判断任务

1. 用户想新画一张图时，使用 `mode:"image"`。用户提供图片只作为主体、风格、构图或氛围参考时，仍是普通生图，传 `references`。
2. 用户想改一张已有图片时，使用 `mode:"image"` 并传原图的 `references`；提示词明确“只改什么、保留什么”。参考图不可读时停止并说明原因，不改成纯文字生图。
3. 用户要你画自己的形象、自拍、近照或穿搭时，使用 `mode:"selfie"`。插件优先读取当前角色的人设图，缺少时使用“自拍形象”里的备用图。明确要求侧面、背面、Q 版或细节时，分别填 `selfieView:"side"`、`"back"`、`"chibi"` 或 `"detail"`，其余情况留空。调用时无需填图的路径，也不要传聊天参考图。自拍是绘图结果。
4. 普通生图与自拍分别开关。方式关闭时说明对应设置。缺少人设图时提示在角色中添加图片，或在“自拍形象”里上传备用图。
5. 工具返回仅主人可用时，告知请求者当前的画图权限。

## 准备提示词

保留用户的主体、风格、画幅、文字和禁忌。请求很具体时只整理成清晰说明；请求很宽泛时才补有帮助的场景、构图与光线。不要凭空增加角色、品牌、对白、道具或剧情。

复杂任务可采用以下顺序，不必每次填满：

```text
用途：图片将用在哪里
主要要求：用户要求的主体与动作
参考图：图1是主体/编辑目标；图2是风格/构图参考
场景与构图：视角、景别、背景与留白
风格与光线：写实、插画、产品图等
画面文字：逐字写出；不添加其他可读文字
约束：必须保留的身份、服装、比例、物体、布局
```

参考图按工具传入顺序从图1编号，并在提示词里说明每张图的作用。用户要求保持角色、脸、布局或原图其他部分时，每次改图都重述这些约束。自拍固定形象应保持同一角色的脸、发型与核心辨识特征，只改变用户指定的场景、表情、姿势或穿搭。

详细提示词原则见 `references/prompting.md`，相关场景的可改写范例见 `references/sample-prompts.md`。只在需要时通过 `useSkill(resource="references/...", ...)` 读取，不要把范例中的设定当成用户要求。

## 调用 draw_image

每次调用生成一张图片。多张不同内容要分别写提示词、分别调用；同一个请求继续查询原任务，不重新提交。工具参数：

```json
{
  "mode": "image",
  "prompt": "完整画面要求",
  "size": "1024x1024",
  "quality": "medium",
  "format": "png",
  "references": [{ "messageId": "真实消息编号", "index": 0 }]
}
```

省略 `provider` 即沿用插件设置；自动服务优先使用当前聊天已配置的 Codex 登录。只有用户明确选择供应商时才传 `provider`。不要为失败的 Codex 任务自行改用 API Key 服务，也不要自动重试可能产生费用的请求。

`references` 接受实际可访问的聊天图片消息编号或当前聊天中插件返回的完整 `url`，最多两张；旧的本插件 `assetRef` 仍兼容。每张参考图只填一种来源，其他插件的私有 assetRef 不能直接使用。不要猜测编号、伪造 Base64 或把网页图当成聊天附件。自拍不传 `references`。尺寸仅支持 `auto`、`1024x1024`、`1536x1024`、`1024x1536`；画质为 `auto`、`low`、`medium`、`high`。`background:"transparent"` 需选用支持透明输出的服务，并搭配 PNG 或 WebP；服务拒绝时说明原因，不悄悄改成不透明图片。各服务差异见 `references/provider-controls.md`。

用户要 GIF 动图时传 `format:"gif"`，提示词写清主体、动作及是否循环；如用户指定帧数或每帧时长，可传 `frameCount`（2–16）和 `frameDurationMs`（20–2000 毫秒）。未指定尺寸时使用自动尺寸。插件通过所选服务请求支持动图的模型；若账号或服务拒绝，说明当前服务不可用，不自动切换到其他计费服务。自拍动图同样沿用固定形象和自拍开关。

用 `action:"start"`、`input` 和稳定的 `requestKey` 启动。用户要几张图，就逐张提交，每张使用自己的 `requestKey` 和简短的 `title`（例如「天使」）。本轮有几条独立画图请求时，用外层 `messageId` 指明这张图对应的原消息。重试原提交沿用原 key。

- `followup:"event"` 表示已提交，`phase:"queued"` 表示排队。可以继续接话，结果会自动回到当前聊天。收到完成事件后，用它提供的图片地址交付。
- 用户问进度或要取图时，用 `{"action":"result","jobId":"启动回执的 id"}` 读取同一聊天的任务和公开结果。回执为 `followup:"poll"`，或早期任务只返回完成状态时，由原提交者用 `status` 查询原任务。
- 补发以前画好的图时，从原任务或当前会话取出图片的完整 URL。用本次补发的 `requestKey` 调用 `recover_image`（`action:"start"`，`input:{"url":"原图片地址"}`）。若还在运行，按它的任务编号查询。用取回结果的 `images[].url` 交付，原图不可用时说明情况。
- 如果上次已提交回复，先核对发送回执。回执为 `unsent` 时，使用新图片地址和新的回复 `requestKey` 提交补发。重试同一次补发沿用该 key。
- 通过通用 `plugin` 查询或取消时，加上 `pluginId:"image-studio"`。取消仅限原提交者。失败、超时或取消后先核对原任务，再决定是否重新提交。

`purpose` 根据当前请求和相关前文的用途填写，不能根据文件格式判断。用户明确要表情包，或要一张用于聊天反应的图（如拿来回复“收到”、装委屈、斗图）时传 `purpose:"sticker"`，静态和动图都适用。前文已经在制作表情，本轮只说“让它动起来”，仍沿用表情用途。

仅要求“画一张动图”、角色自拍、可爱动作、普通绘画或演示动画时，默认 `purpose:"image"`。GIF、有角色或动作夸张本身都不构成表情用途。用途不明确就保持普通图片，不为决定是否收藏额外追问。试验和改稿中间版传 `draft:true`。表情成品发出后，表情插件可按收藏设置自动收录，不重复调用收藏工具；用户随后明确要求收藏普通图片时，可将 `images[].url` 交给收藏工具。

## 核对与交付

收到任务完成事件，或按编号查到 `status:"completed"` 且 `result.images` 有图片时，才确认生成成功。查看图是否符合用户的硬性要求。发送、改图或交给其他插件处理都使用 `images[].url`。结果发过就不重复发；需要回复失败或等待时，用一句日常聊天的话说对方关心的情况。
