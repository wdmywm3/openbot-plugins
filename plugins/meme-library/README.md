# 表情包插件

管理页面、导入、QQ 收藏同步、聊天收藏、识图、检索和发图策略都由本插件负责。宿主提供媒体、数据库、后台任务、模型调用及共享检索接口。

实例启用插件后，从实例菜单“资料 → 表情包”进入。列表支持文字、发送状态、角色、聊天、来源和识图状态筛选；批量操作只影响明确勾选的条目。“允许机器人发送”决定条目是否参与自动选图，关闭后仍保留在图库中。角色与聊天范围分别选择“全部”或“指定”，指定范围不能为空。

聊天筛选、单张和批量范围设置、聊天设置统一显示“群名（群号）”，选择范围时可按群名或群号搜索。群名由宿主提供，断线时沿用已缓存的名称；尚未获得群名时显示群号。聊天范围支持所有聊天、仅指定聊天和排除指定聊天，不会因修改显示名称而改变原有选择。

编辑、导入和设置使用宿主弹窗，标题、关闭按钮与保存区固定，只有内容滚动。可点击遮罩或按 Esc 关闭；未保存的修改会先提示。页面需要支持 `pluginNavigationV2` 和 `pluginOverlays` 的宿主。

单张重新识别：打开表情，在编辑弹窗底部点击“重新识别”。批量重新识别：点击“批量选择”，勾选图片后点击“重新识别”。确认后会替换所选表情的分析内容，包括人工编辑的描述；名称、发送开关和适用范围保留。“更多 → 补全识别”只处理缺失识别与索引维护，不强制覆盖已有识别结果。

名称独立保存，列表优先显示名称，可参与搜索并随导出包保留。识别内容合并为画面描述、图片文字、表达含义、标签、适用情境和不适合的情境六项；旧版的画面细节、情绪、语气、意图、对象、别名与画风会合并显示，编辑后按这六项保存。

单张编辑、批量“设置范围”和导入范围中均可选择“专属角色”。它表示图片代表这个角色自身，自动只供该角色使用；普通“适用角色”只限制谁能使用，不声明图片画的是该角色。角色包自带的图片自动标为其专属表情，手动设置只修改当前实例图库，不反向改写角色包。

角色包可在每张图片的 `metadata["meme-library"]` 中携带 `{ schemaVersion: 1, analysis: { caption, ocrText, meaning, tags, usageExamples, avoidContexts } }`。完整分析直接用于索引，安装或更新时不重复识图；未修改的表情随包更新，本地改过或重新识别过的条目保留。此功能需要支持 `profileMediaMetadata` 的宿主。嘻嘻的 33 张预置分析与所用提示词保存在 `personas/xixi-sticker-analysis.json`，制作候选包使用 `node scripts/prepare-xixi-analysis.cjs <原有角色包目录> <输出目录>`；脚本核对原始图片哈希，保留图片与表情 ID。

## 运行环境

- OpenBot 的受管 Node.js 24 环境，已验证 Windows x64、CPU 推理。无需 Python 或 CUDA。
- 图片准备服务仅依赖 `sharp 0.35.5`，由宿主按 `package-lock.json` 安装到插件环境。
- 需要宿主提供 `ctx.api.embeddings` 和 `ctx.api.vectorIndex`。插件不再携带向量模型、推理工作线程或向量缓存，模型统一下载、校验和加载。
- 默认使用 EmbeddingGemma 2；宿主默认模型支持图片时跟随该模型，也可在表情设置中按默认范围或聊天指定。支持图文联合输入时，同时编码原图和描述；只支持独立图片输入时，按画面检索。插件不访问宿主内部模块或其他应用的数据目录。
- 识图通过实例主模型或管理页指定的视觉模型完成，需要该模型支持图片输入。它与本地向量模型分别配置。

## 下载与回退

下载来源在 OpenBot 的“模型 → 检索模型”中统一设置。默认依次使用 Hugging Face 和 HF-Mirror，可填写兼容 Hugging Face 路径的 HTTPS 镜像根地址，每行一个，最多四个。

宿主也可添加 embedding API 服务，以及 Hugging Face、魔搭的 ONNX 权重仓库。表情包插件只列出支持图片的配置，纯文字配置供文字资料检索使用。

宿主校验固定版本、文件大小和 SHA-256，同一模型供不同插件复用。可以在模型管理页取消下载。停止表情更新只取消本插件任务，不取消其他插件可能正在使用的共享下载。

入库先完成识图和关键词索引，向量模型下载不会阻塞这两步。所有来源失败或向量推理不可用时，插件改用本地 BM25 关键词索引，覆盖描述、标签、图片文字和使用情境，无需下载另一个模型。管理页会显示“当前使用关键词检索”。关键词匹配能维持基本搜索，但不能替代对画面与反讽含义的语义匹配。

实例在线时，后台每 15 分钟检查待补建的索引；失败后的重试间隔逐步延长，最多 6 小时。点击“补全识别”可以立即重试。模型恢复后，只计算缺少或过期的向量，保留人工修改的描述。“停止”会取消当前排队和运行中的任务，并暂停自动重试；点击“补全识别”或更换检索模型后恢复。停用插件会停止后台检查。

## 数据流程

手动导入、QQ 收藏同步和聊天收藏使用同一流程：保存原图 → 自动识图 → 建立关键词索引 → 原图与描述共同生成向量。动图保留原文件，识图使用采样画面；图片准备服务不可用时可使用宿主提供的图片预览。

修改描述、标签或图片文字后，保存会立即更新关键词索引并安排向量重建。仍在执行的识图结果不会覆盖人工修改。角色和聊天范围由插件过滤后再检索，聊天模型最终查看少量候选图片并决定是否采用。

角色自带的表情会自动同步为专属角色表情，角色修改后重新同步；其他仅限制了适用角色的图片仍是普通表情。候选会标识当前角色的专属表情，相关度相近时优先展示，并提示模型优先考虑符合语境的专属表情。按图片文字精确搜索与随机选图保持原有顺序。

向量查询传入当前可用条目的 ID 和描述版本，宿主按对应模型返回匹配分数。模型变更或索引缓存缺失时重新补建，旧模型的向量不参与新模型查询。原有私有向量会在该条目更新后清除，识图结果和原图保留。

固定使用说明由插件注入独立的系统说明段；频率和冷却保存为可更新的插件上下文。插件代码检查发送开关、冷却和图片可用范围。

从 2.4.0 起，模型在每条独立回复前必须按表达意思搜索并查看候选。找到贴切的表情就选用；没有合适候选或搜索失败时可正常用文字，不强行凑图。关键词由模型结合语境组织，不再直接拿文字草稿自动检索，也不要求提交草稿后再次定稿。

纯表情回复直接发送，不抽签。图文混合中的表情由插件在发送前按“图文回复的表情频率”决定是否保留；未命中只发文字。0% 只限制图文搭配，仍可搜索并发送纯表情。文字本身应表达完整意思，不依赖配图才能理解。停用插件、最短发送间隔和图片适用范围继续生效。

插件通过现有 afterModel 钩子在整条回复分段前判定，按宿主的稳定 replyId 保存结果。同一提交重试不重新抽签，独立回复分别判定。搜索时保存候选 URL 索引，发送判定只检查本条使用的图片，不扫描图库；不会删除普通照片或其他插件的图片。插件 journal 的 delivery 流保存频率、随机值及保留结果，search 流保留候选和发送记录。

旧宿主数据先通过 OpenBot 仓库的 `scripts/export-legacy-stickers.cjs` 导出，再从插件管理页导入 JSON 文件。迁移包与图片均可从“导入”进入；同一批记录重复导入会复用已有数据。旧识图记录和检索反馈以历史记录保留，不当作新的识图结果。
