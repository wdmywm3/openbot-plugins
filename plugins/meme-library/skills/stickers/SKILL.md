---
name: stickers
description: 在聊天中按表达含义检索表情、查看候选原图，或收藏值得以后复用的聊天表情。
---

先决定是否回应、回应谁。当前可用时，每条独立回复提交 qqReply 前必须先搜索一次并查看候选；一条合并回复搜索一次，不按人数重复搜索。可以主动选择纯表情，无需等用户索要。表情合适时可以只发一张图，表达完整就结束，不补同义文字。

调用本插件的 stickers 工具，action=search，query 写自己这次想表达的意思、态度和对象，不直接照抄含糊的短台词，也不只堆角色名、猫娘、可爱等外观词；找画面时写具体视觉特征。找图上的原文可用 mode=text。查看候选图片、含义和 avoidContexts；roleSticker 为 true 的候选是当前角色的专属角色表情，符合语境时优先选择。没有合适的就用文字，不反复换同义词搜，也不据此认定整个图库为空。

发送时把候选返回的完整 url 原样放入 qqReply：`<image src="工具返回的完整url"/>`。不要编造图片地址。模型的思考、候选预览、收藏动作都不等于已发送。

专属角色表情表示当前角色的形象，普通梗图不会改变人设。看清图中的嘲讽指向，区分画面情绪与发图者真实意图；不把别人发图时的对象照搬进自己的回复。对方继续斗图时可以接招，停下、换题或认真说事就收住，不追发。

值得以后复用的聊天表情可以用 action=collect，提供当前聊天消息的 messageId 与从 0 开始的 imageIndex。收藏后自动识图并建立索引，不轮询等待，也不反复收藏。普通照片、私人截图和聊天身份关系不当作表情收集。关闭表情时遵循当前插件设置。

管理页面修改描述、文字或标签后会自动更新索引。识图先生成可编辑的描述，再通过共享检索模型建立索引；图文联合模型同时使用原图和描述。人工编辑优先于仍在执行的识图结果。检索模型不可用时仍可按文字查找，候选是否合适继续由你结合当前聊天和原图判断。

纯表情回复直接发送，不参与频率抽签。图文混合中的表情由插件在发送前按设置频率决定是否保留；文字本身应能表达完整意思，不写“看这张图”等依赖表情的说明。不要自行抽签或因频率低而跳过搜索；0% 只表示图文回复不附带表情，仍可搜索并发纯表情。无结果、候选不合适或搜索失败时可以直接发文字，不强行凑图；候选不合适可用 action=no_match 记录原因。正常提交最终回复即可，不提交草稿、不等待选图提醒；同一提交重试沿用原 requestKey 和搜索结果。
