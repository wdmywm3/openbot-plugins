---
name: stickers
description: 在聊天中按表达含义检索表情、查看候选原图，或收藏值得以后复用的聊天表情。
---

先决定是否回应、回应谁。当前可用时，每条独立回复提交 qqReply 前必须先搜索一次并查看候选；一条合并回复搜索一次，不按人数重复搜索。可以主动选择纯表情，无需等用户索要。表情合适时可以只发一张图，表达完整就结束，不补同义文字。

调用 `plugin__meme-library__stickers`，外层传 `action=start` 和稳定的 `requestKey`，在 `input` 内传 `action=search`、`query` 和本次用途 `usage`。用户明确索要表情、正在斗图，或删掉图片就不能完成这条回复时用 `usage=required`；文字已经完整、顺便配图时用 `usage=optional`。不要仅因为“配图更有趣”就标记为必要表情。任务回执为 `running` 时用 `action=status` 和 `jobId` 查询。

用具体语境写 `query`，例如「被夸后得意叉腰」或「想拿空筷子蹭一口」。找图片上的原话时用 `mode=text`。想用填字表情时加 `kind=template`，按用途搜索，例如「半垂眼想吐槽的思考框」。结合候选图片、含义和 `avoidContexts` 判断。语境贴合时优先选择 `roleSticker: true` 的专属角色表情。没有合适的候选就用文字。

发送时把候选返回的完整 url 原样放入 qqReply：`<image src="工具返回的完整url"/>`。不要编造图片地址。模型的思考、候选预览、收藏动作都不等于已发送。

候选标记 `textTemplate: true` 时是可填字表情，没有直接发送的 url。合适时用同一工具调用 `action=render`，传搜索结果的 `searchId`、候选 `id` 和想写进图里的 `text`；取得返回的 url 后按普通图片发送。`text` 是你打算公开表达的短句，思考框尽量在 20 字以内，可以是想法、自然的梗或熟人间轻轻的吐槽，例如“白痴”，随当前关系和语境决定；不要将私有思考或工具说明写入图片，也不把取笑变成人身攻击。对方认真求助、表现不舒服或停止玩闹时收住。图片已把意思表达完整时不需要复述。

专属角色表情表示当前角色的形象，普通梗图不会改变人设。看清图中的嘲讽指向，区分画面情绪与发图者真实意图；不把别人发图时的对象照搬进自己的回复。对方继续斗图时可以接招，停下、换题或认真说事就收住，不追发。

用户明确要求收藏、出现图库缺少且以后能表达明确意思的新表情、或形成当前聊天的常用梗时，主动用 action=collect 收藏。聊天图片传 messageId 与从 0 开始的 imageIndex；工具生成或处理的图片传工具返回的完整 url，二者只选一种。收藏后在后台识图、建立索引，不轮询等待，不重复收藏。普通照片、私人截图、演示动画和改稿中间版不自动收藏。

制作自用聊天表情时在绘图工具中声明 purpose=sticker，静态和动图都适用；试验或改稿中间版声明 draft=true。合格成品发出后，启用了自制表情收藏的插件会自动收录，不需要再调用一次收藏工具。自动收藏关闭时，用户明确要求收藏仍应调用 action=collect。不要只凭 GIF 格式判断它是表情。

管理页面修改描述、文字或标签后会自动更新索引。识图先生成可编辑的描述，再通过共享检索模型建立索引；图文联合模型同时使用原图和描述。人工编辑优先于仍在执行的识图结果。检索模型不可用时仍可按文字查找，候选是否合适继续由你结合当前聊天和原图判断。

必要表情和纯表情回复直接发送，不参与随手配图的概率抽签和冷却。图文中的随手配图按设置频率保留，这种回复的文字应能独立表达完整意思。需要图片才能成立的文字须搭配本次 usage=required 搜索得到的图片。不要自行抽签或因频率低、随手配图冷却而跳过搜索；0% 仍可发必要表情和纯表情。每条独立回复重新搜索，同一提交重试复用原搜索；旧图片地址不沿用先前的必要用途。无结果、候选不合适或搜索失败时可以直接发文字，不强行凑图；候选不合适可用 action=no_match 记录原因。正常提交最终回复即可，不提交草稿、不等待选图提醒；同一提交重试沿用原 requestKey 和搜索结果。
