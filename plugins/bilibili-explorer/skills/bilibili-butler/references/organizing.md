# 三级整理与恢复

## 共同准备

先用 `folders` 获取真实收藏夹 ID 和名称，结合用户规则判断用途。用 `scan` 扫描选定收藏夹，继续分页直到完成；保留 scanId。默认只分类，只有用户要求实际整理才设 previewOnly=false。初级是默认级别；用户只要求初级时，不额外转写或下载视频。开启自动备份属于独立设置，不由分析级别自动开启。

每个 BV 的分析与收藏位置无关。先读取已有记录；搬家、重复收藏不重做同一分析。按分 P 保存结论，不能以第一 P 代表全片。分类通常选一个主类：AI 剪辑工作流归 AI，普通剪辑技巧归视频剪辑；多个独立重点才多选，不按出现的所有名词拆散。

## 初级：标题、简介、标签

`classify(scanId)` 默认每批最多三个视频，综合三个字段判断重点。标签可能蹭热点，不能代替正文。继续到方案 ready，`preview(planId,offset)` 分页查看。只掌握元数据时，不判“无内容营销”，不声称已经观看。

## 中级：正文与评论

逐个调用 `review(bvid,part,level=medium)`，返回 analyzing 时继续相同输入，外层每次新的任务批次使用新的 requestKey。优先字幕；缺失或有明显断裂、错误、信息不足时转写音频。转写使用用户选择的 MCP，不自行安装或更改模型。中级不读取画面，依赖画面的疑点留待高级核对。

评论默认最多 30 条，可配置 0–50；从热门与最新各取一页（每页最多 20），包括取得的置顶项，按评论 ID 去重，不递归楼中楼，因此实际数量可能低于上限。记录抓取时间、样本范围和失败情况。无法读取不等于评论为空，更不代表没有有效评论。

逐项评估这一个视频：

- **承诺兑现**：标题承诺什么，正文是否给出对应结论或方法？
- **具体信息**：有无可复核事实、对比条件、实验、案例或可执行步骤？“速度快、很强”本身不构成教程。
- **资源可获得性**：若承诺分享某个 skill/工具，是否给出可定位的项目名、文档或下载入口？没有直接链接但能找到明确项目，不等于没有资源。
- **资料门槛**：关键内容是否必须关注、留言、加微信或公众号后才能获得？记录原文和位置；不自行关注、私信或添加联系人。
- **评论的旁证**：重复的“已关注、求资料”可支持“领取资料为主”的观察；样本偏差必须保留，不能推断刷量或整个评论区都如此。

只有承诺未兑现、正文空泛和引流等证据相互支持时，才提示营销风险。AI 制作、商业赞助、夸张标题、单独缺链接或少量评论都不足以单独下结论。新闻、观点、娱乐内容不强求下载链接或教程。分为有用、优缺点混合、营销风险、资料不足；后两种保留待核对。给出来源、短引文、时间戳/评论 ID、建议；不据此自动删除，不给整个账号贴标签。

## 高级：画面与总结

调用 `review(...,level=advanced)`，沿用已完成中级的字幕、转写和文字笔记，再读取画面。优先核对界面、步骤、图表、演示结果和资源入口，标注抽样覆盖范围；抽帧不是逐帧观看。缺少视觉能力时写明尚未完成画面核对。

总结实际主题、关键事实与作者主张、具体步骤、可复用资源、时间戳、适用条件和局限；区分“作者声称”与已验证事实。长视频分段持久化后分层合并。缺失区间不补写。

完成中级或高级评估后，重新 `scan(reset=true)`、`classify` 生成结合正文的新方案；已有方案保持冻结。初步分类缓存会因内容依据变化重新判断，但已有正文不用重读。`refresh=true` 只用于明确需要重新取得资料或修复不完整分析；开始后继续调用不要反复带 refresh。

## 收藏变更与撤销

`apply(planId)` 实际复制/移动当前方案。先确认全部目标收藏，再移除源收藏。保存 BV/AID、标题、源/目标夹、理由、操作前状态及每步结果。网络结果不明时核对状态，不盲目再次提交。

独立操作：

| 工具 | 用途 |
| --- | --- |
| remove | 从指定 folderId 移除 bvid；必须给 reason 和稳定 operationId |
| create_folder | 新建 title，intro 可选；默认 private=true，返回真实 folderId |
| delete_folder | 分页保存完整清单、核对后删除；preparing/backing_up 时沿用 operationId 继续 |
| undo | 按 operationId 恢复；restoring 时继续，reverted 为完成 |

这些操作只按用户要求执行；同一 operationId 必须保持参数不变。恢复移动先恢复源收藏，再移除本次新增目标；原已存在的目标保留。删除收藏夹会重建新 ID，无法恢复原 ID、原收藏时间；平台已删除的视频可能无法重新收藏，但编号与失败原因保留。新建收藏夹已有新内容或设置变化时，不自动删除来“撤销”。用户可在“操作记录”一键撤销；这不是第二套运行日志。

## 本地备份

开启插件的备份开关并绑定 mediaServices.backup 后，后台按设置间隔扫描待整理收藏夹（列表为空则扫描全部）。每轮分批处理，按 BV+分P 去重，串行下载并随机间隔请求。也可 `backup(bvid)` 或 `backup(scanId)`；未完成则继续。所有分 P 完成才报整条视频已备份。

文件保留在用户配置的目录，按实例隔离；保存大小、SHA-256、来源和标题。取消收藏或卸载插件不会删除备份文件。开启备份后，实际移除收藏前要求备份完成并校验；失败保留原收藏。不会绕过平台权限；失效、登录限制、限流或磁盘不足都记录原因，不当作已备份。

下载失败或本地文件损坏后可 `backup(bvid,retry=true)` 明确开始新尝试，后续查询不再带 retry。备份默认关闭，不默认下载整个收藏库。配置方法见插件根目录 MEDIA.md。

## 参考项目（2026-10-21 查阅）

- [DeArrow](https://github.com/ajayyy/DeArrow)：众包更准确的标题与缩略图。借鉴标题与实际内容的区分，不把它当自动营销识别器。
- [SponsorBlock](https://github.com/ajayyy/SponsorBlock)：众包标注推广等片段。借鉴可定位的分段证据，不直接给整个视频或作者定性。
- [bili-sync](https://github.com/amtoaer/bili-sync)：收藏夹/列表同步下载、数据库去重、请求频率控制及风控后停止。采用相同的去重与暂停原则；当前下载执行复用可选媒体 MCP 的 yt-dlp，并未引入它的二进制。

没有把这些项目宣称为现成的 B 站 AI 营销号分类器；当前价值评估是管家的模型工作流，需要用实际样本持续检验。
