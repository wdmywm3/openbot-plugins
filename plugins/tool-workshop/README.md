# 工具工坊

让 Bot 在主人私聊中编写 JavaScript 工具，经过试运行后保存，后续直接调用。支持文本与数据处理，以及分别允许后的 HTTP、模型调用和媒体保存；例如让 Bot 自己写一个通过已登录模型画图并发布图片的工具。需要支持 `scriptExecution` 及相应显式能力的 OpenBot。

启用插件后，可以对 Bot 说：“写一个整理文本空白的工具，测试后保存；以后用它整理我提供的文本。”Bot 通过固定的 `manage`、`run` 两个入口管理工具，不需要修改宿主或为每个工具重新安装插件。

流程为：列出现有工具 → 创建草稿及参数规则 → 试运行并核对输出 → 保存 → 按已保存版本执行。修改草稿保留原来的已保存版本，试运行成功后再次保存才替换。删除重建会获得新版本，迟到的旧试运行不能给新代码放行；同一版本并发试运行采用最近启动的那一次。工具和版本保存在当前私聊的插件状态中，最多 20 个工具。

代码导出 `module.exports.run = async ctx => ...`，输入为 `ctx.input`，返回 JSON 值。参数规则采用有限 JSON Schema 子集：基本类型、嵌套对象与数组、必填、简单枚举、数值及长度范围；对象必须设置 `additionalProperties:false`。

生成代码在独立、一次性的后台 worker 中运行，沿用宿主的原生插件 VM 约束；不开放模块导入、动态代码生成、本机文件、宿主状态或凭据读取。代码最多 48 KiB，输入最多 60 KiB，最终输出最多 256 KiB，执行最长 180 秒；模型调用的中间结果可达 8 MiB，图片通过媒体接口保存后只返回引用。普通工具默认 3 秒，声明模型能力的工具默认 180 秒。宿主限制并发、排队及 API 调用，并在超时、取消、停用后终止工作。该执行边界不是操作系统沙箱。

三个开关默认关闭：允许工具联网、允许工具调用模型、允许工具保存媒体。草稿按实际需要声明 `request`、`modelRequest`、`assets`，只得到所声明且当前设置允许的接口。模型请求由宿主绑定实例模型或明确选择的模型，宿主保管凭据；媒体按插件、实例和聊天范围保存。关闭开关后，已保存的工具也不能再次调用对应能力。

HTTP 沿用插件已批准的网络权限；不开放 multipart 或凭据读取。模型调用与联网试运行都可能消耗额度，失败后不自动换服务或重复提交。插件自己负责 API 参数、状态、结果核对及异常处理。

例如公开 API 查询可写成：

```js
module.exports.run = async ctx => {
  const response = await ctx.api.request('https://example.org/status', { responseType: 'json' });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.body;
};
```

示例地址用于说明接口，需要换成用户指定的真实服务。Skill 包含让 Bot 编写绘图源码的示例：通过 `modelRequest` 调用已配置模型的原生画图能力，用 `assets` 保存和发布图片，再返回当前聊天可发送的地址。工坊不会预装这段工具或把已有 `draw_image` 包装成新写的代码。账号仍需实际支持原生画图；独立 API Key 服务若未接入宿主模型，不能直接取得其凭据。

运行测试：`node tests/tool-workshop.cjs`。
