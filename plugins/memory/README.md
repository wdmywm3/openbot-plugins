# 记忆 Plus

这是 OpenBot 的可选记忆策略插件。基础记忆、正文存储、历史、遗忘和共享由新版宿主提供；无需安装本插件也能使用宿主 memory 工具。笔记不再是独立类型。

## 使用

2.4.0 为每个聊天保留持续整理会话，按内容容量从旧到新追加批次，通过工具查询、核对和提交记忆。输入保留双方实际聊天，不把工具日志、思考或召回注入重复作为新增资料；暂不自动新增经历。整理失败可重试，已提交的批次不会重复写入。

人物画像按实例、聊天和成员分别保存，只采用本人确认的事实与偏好，保留原话和修订关系；事件事实与事项另存。同一人在不同群中的画像互不合并，原有常用称呼、别名和备注保留。定时整理与宿主的临时关注分别开关。

2.3.4 将自动召回限定为本轮回复目标的正式记忆匹配，最多注入四条，检索预算约两秒；同批旁聊只提供上下文。需要查原始聊天或图片历史时，模型通过 `recall(searchIn="chat_history")` 按需检索。现有历史索引、闲置整理设置及图片检索能力继续可用。

2.3.3 修复实例已开启整理、后台却读取为关闭的问题。升级后沿用已保存的闲置时间和聊天覆盖，安静达到设定时间且有新资料时自动整理；无需重新配置。整理和记忆使用评估的 Token 会计入“记忆整理”。仍需 OpenBot 0.1.92 或更新版本。

2.4.0 需要支持持续整理会话和人物画像的新宿主，本次配套安装包为 OpenBot 0.1.98。安装时会检查 `agentContinuations`、`memoryCategories` 等声明能力；请先安装配套宿主，再更新插件。宿主为本地向量计算提供动态批处理与 CPU 有限并行；本插件声明独立取消协议，单次召回超时不会终止同进程的后台索引。

安装本目录的 ZIP、准备 Node.js 24 并授权，绑定到实例。插件需要宿主统一记忆协议 v2 及 `persistentContextItems` 能力；旧宿主缺少能力时明确报错，不回退写入旧正文或每轮重发召回快照。

2.3.1 修复多图聊天触发 32 MiB 进程消息限制的问题。召回钩子通过宿主的 `modelHookTextInput` 接口只接收文字和附件元数据，原图按需通过已有来源接口读取，模型的图片输入保持完整。此版本需先更新至 OpenBot 0.1.91 或提供该能力的更新版本。

自动召回提交固定版本与片段引用。宿主只追加当前上下文尚未包含的条目；换话题不会撤走先前资料，普通修订追加新版本，压缩移除后可重新补入。遗忘、来源删除或撤销授权后，旧引用不继续提供正文。

自动召回和 `recall` 工具融合关键词与语义检索。选择 EmbeddingGemma 2 等图文模型时，还会为可访问的聊天图片和记忆来源图片建立图文索引。自动召回按发言插入资料引用；`recall` 可返回最多四张获授权记忆原图。图片下载失败不阻断文字索引，后台另行重试。图片向量不会自动生成 OCR 或画面描述，建立图片索引也不等于新增正式记忆。

统一模型在“模型 → 检索模型”中管理，默认自动使用 GPU、不可用时回退 CPU。旧派生索引会逐步补建图片部分；已遗忘的记忆不会因此恢复。需要本轮只查图片时，给 `recall` 传入 `imageMessageId`，多张图片用从 0 开始的 `imageIndex` 选择。

在实例菜单“资料 → 记忆”中查看或修改正文。启用 Plus 后，同页增加“整理”页签，管理整理设置、运行记录、回滚和维护建议，并沿用当前选择的聊天。整理默认关闭；设置自动保存，支持实例默认值和聊天覆盖。停用插件保留宿主记忆。

在实例的插件详情中，可把页面入口改为独立分类，显示“整理”和“运行记录”；两种布局互斥，不会同时显示重复入口。完整记忆页面替换由宿主的通用接口支持，本插件当前保留内置正文编辑页。管理页面需要 `pluginNavigationV2` 和 `pluginOverlays`；日志详情与确认操作使用宿主弹窗。

定时、空闲和手动整理共用每个聊天的持久断点，只处理上次成功提交之后的新资料。一次运行固定资料上界，分批成功后推进断点；失败或单纯轮询不推进，重启后继续未完成批次。成功检查但没有值得保存的内容，也会记录进度。

在所选聊天的“整理”页中可点击“跳过此前记录”，将起点移到当前资料末尾，之后处理新记录；已有记忆不受影响。运行中的整理或复查需要先停止。此操作保留审计记录，重复提交同一 requestKey 不会再次推进。实例级管理调用也可对所有当前聊天设置起点。整理不要求每批产生记忆，一次互动或工具故障不自动变成长久偏好。

## 策略

宿主提供统一读写、查询、修订历史、遗忘、层级变更、权限和共享，以及模型、向量索引、来源事件与后台任务等通用接口。升级降级、保留归档、自动召回和 Dream 的判断规则均由 Plus 决定；用户也可以手动修改宿主记忆。Dream 不存在另一套宿主专用实现。

Dream 使用通用证据与质量规则，再分别加入群聊、私聊和主人事项的整理要求。群聊区分成员与交错话题，不自动安排私人事项；私聊只采用当前对话方的偏好与反馈；主人私聊可包含并行事项，换话题不自动接续上一项。主人关系取自宿主实际聊天身份，在后台沿用最近一次确认；未获确认时采用普通私聊规则，管理页面或后台作业权限不能用来推断主人身份。关系只辅助整理，不授予操作权限。

只有明确约定的 followup 才安排复查。改期同步更新复查时间；未修改的周期、按新消息复查和工作事项订阅保持原值，也可显式清除。完成、取消或关闭停止复查，明确重新开启时不会恢复旧订阅。截止日期、闲谈愿望或模型自述完成不会自动变成已安排的任务。

- 从有权限的实际聊天中提取事实、偏好与事项，核对原文摘录与版本。暂不自动新增经历，历史经历仍可查看。
- 通过宿主共享向量索引和文字匹配发现候选，再按对象、条件、有效时间、来源及当前修订过滤。
- 按冻结批次整理，保存提案与游标；失败退避，恢复时复用幂等提交。
- 只根据实际送达回答评估是否采用或误用；检索命中本身不计为采用。
- 长期保留和归档形成可确认建议；未完成事项不自动归档。
- 到期复查使用独立只读任务，区分完成、部分完成与阻塞；只有有用变化才提交通知。通知入队不等于 QQ 已送达。

固定说明和本轮资料经 beforeModel 提供，不修改人设。可配置 retrievalModelId 使用宿主已配置的检索模型；未就绪时使用文字检索并后台补建。索引、评分和检查点都是派生数据，不能在宿主拒绝读取时作为备用正文。

## 迁移

旧插件事实、事项、历史与 Markdown 经公共导入契约写入宿主。迁移先保留数据库和文件快照，保存旧编号到新引用的映射；相同输入可重复导入。缺失正文或冲突明确报告。

早期宿主数据先退出旧应用并备份，再在宿主源码中运行：

```powershell
node scripts/export-legacy-memory.cjs "D:\OpenBot" "实例ID" "D:\memory-export.json"
```

在插件页面导入该文件。旧运行与回滚日志保留，可转换的修改使用宿主补偿修订，无法转换的项显示冲突。旧复查与恢复快照中的自动整理默认暂停，不自动重新发送历史结果。

旧 runtime.cjs 和 lib/ 中的数据写入实现仅供格式导入及迁移回归使用。process.cjs 的正常入口是 unified-runtime.cjs；统一宿主记录是唯一运行时记忆正文来源。

## 开发验证

`npm run test:memory` 覆盖迁移、策略、真实宿主进程、共享索引、来源撤销、回滚和生命周期，属于宿主集成测试。仓库默认测试使用不依赖宿主源码的 `npm run test:memory:unit`。设置 `OPENBOT_TEST_MEMORY_UI=1` 可检查浏览器中的策略设置、整理起点与日志。发布前需另做真实 QQ 和模型服务验收。
## 召回与图片索引

自动召回围绕本轮回复目标查正式记忆，优先处理主问题，旁聊只帮助理解追问。目标发言中的文字和图片可以匹配正式记忆，图文结果合并去重后紧跟对应发言，放在同一个 `user` 消息内部的参考资料行；每轮最多四条。没有正式记忆时直接继续聊天，不自动改查原始群聊。

前台自动召回共享约两秒的检索预算，慢查询可以使用已有的文字匹配结果。主动调用 `recall` 时默认查正式记忆；指定 `searchIn="chat_history"` 可检索原始聊天和图片历史，文字用 `query`，图片用真实 `imageMessageId` 和 `imageIndex`。结果只返回少量匹配片段及消息编号，原始资料仍须按上下文核对。主动工具检索使用工具返回消息。

普通用户消息的文字和图片也会分批进入 `chat-sources-v1` 索引，无需先生成正式记忆。后台扫描已有聊天并增量处理新消息，图片下载失败单独重试；不支持图片的检索模型仅建立文字索引。检索模型须具备 `image` 能力才能进行图片向量召回。

向量和检索分块保存在宿主 `context/retrieval.sqlite`，来源版本、断点及图片重试信息保存在插件自己的 `memory.sqlite`。图片原件按内容寻址保存在宿主媒体目录，通过授权引用读取；不向 PNG/JPG 写入召回结果。会话只保存来源或记忆的编号、版本、片段范围及插入位置，请求时读取正文。图片向量不等同于 OCR 或图片描述；原消息文字和附件序号随来源引用提供。
