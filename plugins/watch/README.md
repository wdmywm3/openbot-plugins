# Watch 视频阅读

Watch 0.8.0 是通用视频阅读插件：先查看编号分镜图与对应字幕，再按问题高清补看关键片段。聊天附件、视频直链、平台页面与本地文件共用 `watch_start` 入口；工具负责预览、下载、抽帧、字幕、补看与取消，`watch_media` 为其他插件提供异步媒体读取。它使用 OpenBot 公开的 Skill、消息附件和 MCP 接口，业务逻辑和校验全部在本包内。适用于启用此插件的群聊、私聊和任务，不需要给聊天开放 Shell。

`watch_preview` 直接读取B站指定分P的平台预览拼图，最多返回三张低清画面，不下载或解码视频。需要 Pillow（已列入 requirements-media.txt）；返回实际采样时间与请求时间。它适合初筛题材和风格，具体过程、小字或语音仍需按问题补读。预览不可用时返回 unavailable，由调用方决定是否读取原视频。B站小管家 1.12.0 默认绑定此预览工具，需要支持 `preview` 媒体能力的 OpenBot；旧版宿主继续原视频阅读路径。

B站小管家 1.9.0 默认通过 `watch_media` 补读语音和画面。两者在同一实例启用并授权后即可使用；回执按调用方和任务范围隔离，已有任务不会因查询而重新下载，后续补看可复用本范围的来源文件。语音请求实际调用已配置的转写模型，不把字幕冒充语音转写；缺少模型时明确返回不可用。抽样画面保留实际时间及未采样间隔。

支持公共 HTTP/HTTPS 视频直链、yt-dlp 支持的平台页面（包括 B 站、b23.tv、YouTube 等）、当前聊天的真实视频附件，以及配置目录内的本地视频。附件入口使用通用消息接口，不绑定 QQ。画面以图片交给当前模型理解，只需图片输入能力，无需原生视频模型，不额外接入分析模型。字幕优先选择原语言的发布者字幕或自动字幕；无字幕时使用配置好的本地 faster-whisper 模型。登录、付费、DRM、直播与下载器尚不支持的来源仍可能不可用。

| 来源 | `watch_start` 参数 |
| --- | --- |
| 当前聊天的视频附件 | `message_id`，可选 `attachment_index`（从0开始） |
| 视频直链 | `source`；无扩展名时加 `source_type: "direct"` |
| 平台视频页面 | `source`；需要明确按页面解析时加 `source_type: "page"` |
| 本地视频 | `source` 传绝对路径或 `file:` URI，先配置“本地视频目录” |
| 已导入文件或已完成任务 | `source: "import:<token>"` 或 `"watch:<job_id>"` |

`source` 与 `message_id` 二选一。网络地址的签名参数会保留；B 站、YouTube 的标准视频链接保留已有规范化处理。直接文件与本地文件不依赖 yt-dlp。读取公共网络时校验实际连接地址，禁止访问回环和内网；不使用其他应用的浏览器配置或数据目录。

Skill 对平台页面优先使用已授权的 OpenBot 内置浏览器：打开和读取页面，按需点击进入实际视频或分集，再把确认后的页面地址或完整直链交给 Watch。当前浏览器没有文件下载接口，因此视频文件仍由 Watch 获取；浏览器登录状态也不会自动传入下载器。浏览器不可用时可直接解析原链接，明确的权限拒绝不能绕过。直接文件、缓存附件与本地视频无需先打开网页。

## 安装和运行

Watch 0.8.0 的通用附件与本地文件入口需要 OpenBot 0.1.76 或更新版本。该版本提供通用的 `native_tools` 声明，使插件自己的导入接口不会暴露给聊天模型。请先更新宿主，再从插件市场升级 Watch。

1. 使用支持依赖安装的新版本 OpenBot。安装弹窗会使用自带 Python 和 uv，按 requirements-media.lock 准备独立环境，并下载 FFmpeg/ffprobe 与 Deno；无需手动安装 Python 或修改系统 PATH。旧版宿主仍需自行准备这些依赖。
2. 在 OpenBot 的插件管理中导入本目录或从市场安装，在插件详情打开运行开关；再在目标实例或主人私聊中允许暴露插件工具。安装完成和启动状态分别以实际结果为准，查看画面需要支持图片的模型。
3. 向 Bot 提供视频链接和问题。`watch_info` 可检查依赖；不要用执行脚本代替缺失的工具权限。

手动部署到其他宿主时，可从插件目录安装下载依赖：

```powershell
python -m pip install -r requirements-media.txt
```

插件优先使用当前 Python 环境中的 yt-dlp。B 站的 WBI 兼容处理需要这个 Python 包；YouTube 所需的 EJS 组件由 `yt-dlp[default]` 提供。`watch_info.download_runtime` 分别报告 Python 下载包、EJS 和 Deno 是否可用。

`mcp.json` 使用 `${PLUGIN_ROOT}` 与 `${PLUGIN_DATA}`，没有硬编码宿主路径。每个实例有独立的数据目录。MCP 是包内工具的传输方式，无须另装一个“媒体 MCP”插件。

工具包括 `watch_preview`、`watch_info`、`watch_start`、`watch_status`、`watch_storyboard`、`watch_zoom`、`watch_frames`、`watch_transcript`、`watch_cancel`，以及供其他插件调用的 `watch_media`。工具参数以发现的 JSON Schema 为准。服务通过 stdio 运行，标准输出只用于 MCP 消息。

## 分镜概览与高清补看

`watch_start` 完成后，用 `watch_storyboard({job_id})` 一次读取分镜图片和时间、字幕索引。每页最多12格，最多两页；`next_page` 非空时继续读取。每格提供实际取帧时间、关联区间及字幕节选。字幕保留原时间，节选被截断时明确标记；完整文字仍由 `watch_transcript` 分页读取。相同画面合并存储后，各观察时刻仍有独立分镜编号。

`watch_zoom({job_id,cell_id})` 从该任务缓存的原视频重新读取对应区间，默认抽取6个采样位置，返回新的任务编号；完成后用 `watch_frames` 查看独立画面。分镜编号绑定不可变的原任务，新概览和服务重启不会覆盖旧编号。补看可带 `crop`，不填时返回整帧。旧版本任务没有分镜索引时，原有画面、字幕和按时间补看仍可使用。

默认的 `balanced` 采样依据画面变化与字幕密度分配区间，保留首尾锚点，并在中间区间的多个候选中选清晰帧。变化密度权重设有上限，静态区间不会被挤掉。候选缩略图一次解码，选定画面再按原清晰度提取；候选文件随即清理。显式 `timestamps` 和 `uniform` 保持指定时间及等距采样语义，不做清晰帧偏移。自动选帧失败时会说明原因并退回定时采样，取消操作不会被当作降级继续运行。

分镜图保留整幅画面比例与边缘，只供概览；不把小字和连续动作压在更多子格中。`image_rect` 标明各格图片在拼图中的实际位置，`source_view` 标明原视频尺寸与已有裁剪区域，局部补看按原视频像素指定。低帧率等原因导致区间没有可用画面时，`storyboard.missing_cells` 记录缺口，不将区间外的图片标成该格。图片成本由所用模型决定，不承诺固定 token 数。

## 什么时候读取、如何重看

群聊、私聊与后台任务统一按上下文判断：只有视频内容影响当前理解、回答或任务结果时才读取。已有文字足够时保留附件，不因为收到视频而自动解析；也不要求用户必须说出特定关键词。

短任务可由主 Agent 读取；长片、多个视频或耗时转写可交给已授权的后台子代理。支持 `subagent.start(background: true)` 的 OpenBot 会让当前聊天继续处理其他消息，任务结束后排队通知主 Agent 读取报告、决定是否补充回复。子代理不直接向 QQ 发消息。停止实例或退出应用会取消后台任务；没有可用子代理时仍可使用 Watch 自己的异步任务。

要求重看时，用缓存的 `watch:<job_id>`、新请求编号和新的时间范围或采样点重新取证；已完成的子代理也可以通过 `followup` 接受新问题。不能只把旧摘要重新转述。缓存过期则重新获取来源。

默认读取完整画面。代码、小字或按钮看不清时，可在补看请求中加入 `crop: {"x": 100, "y": 200, "width": 640, "height": 180}`。坐标以 `watch_status` 返回的 `media.width`、`media.height` 为准，表示原视频像素；从缩小后的整帧定位时需换算，不能直接照搬图片坐标。裁剪从缓存的原视频解码后进行，再按图片大小限制缩放，不放大低清截图。实际图片尺寸和裁剪区域随画面返回；不填写 `crop` 就继续读取整帧。

## 可选：登录与语音转写

来源允许匿名读取时可直接使用。网站也可能对公开视频要求登录验证；这时由主人把 Netscape 格式的 Cookie 文件放到本实例插件数据目录的 `cookies.txt`。本插件不会读取浏览器或其他应用的登录资料；Cookie 也不会返回给模型。请只使用有权访问的视频。

本地转写在运行服务的同一 Python 环境中执行 `python -m pip install -r requirements-asr.txt`，另行准备 [faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small) 模型目录，至少包含 `model.bin`、`config.json`、`tokenizer.json`。在插件数据目录新建 `settings.json`：

```json
{
  "asr_model_path": "D:/Models/faster-whisper-small"
}
```

重启该插件的 MCP 连接后生效。转写使用本地 CPU/int8，模型和分词器只从指定目录读取，不在工具调用过程中安装依赖或下载权重。音频由 FFmpeg 准备成单声道 16 kHz PCM，直接交给转写模型，避免再次经过 PyAV 解码。没有字幕且未配置转写时，结果明确标记缺少语音证据。模型和视频缓存均不打包进插件。

## 聊天附件与本地视频

安装或升级后，为 Watch 启用“聊天记录”和 MCP 权限，并启用它的 Skill 与工具。聊天附件由原生 `watch_start` 读取当前聊天的真实消息，再通过插件内部接口传入解码服务；模型不能给内部接口指定任意读取目录。MCP 工具列表对模型隐藏该内部接口，原生与 MCP 的开始入口不会重复展示。

优先使用宿主已缓存的附件，目前宿主单次附件读取上限为6 MiB。较大附件若保留可用原始地址，则直接下载；只有本地缓存且超过该上限时，需要可访问的原始视频地址，或把视频所在目录配置为“本地视频目录”。分块传输可重试，单块低于宿主工具参数上限；任务与临时上传按24小时保留策略清理。

在插件设置的“本地视频目录”中添加允许读取的目录或具体视频文件，例如 `D:/Videos`。默认列表为空；解析符号链接后的文件仍需位于允许范围内。这里指运行 OpenBot 的电脑。独立 MCP 使用者在服务数据目录的 `settings.json` 添加 `"local_roots": ["D:/Videos"]`，通过 MCP `watch_start` 传路径；独立 MCP 的入口不包含聊天消息编号。

原有主动导入方式继续可用，尤其适合同时提供字幕的文件：

主人在终端执行以下命令，其中数据目录须为该实例插件 MCP 的数据目录：

```powershell
python -B tools/server.py --data-dir 'D:/OpenBotData/mcp/ext-example' --import-file 'D:/Videos/demo.mp4' --subtitles 'D:/Videos/demo.vtt'
```

`--subtitles` 可省略，支持 VTT、SRT、JSON3 和 B 站 JSON 字幕。命令复制视频并返回 `import:<随机标识>`；把这个标识交给原会话即可读取。普通聊天附件和视频直链无需这一步。常见文件格式包括 MP4、MKV、WebM、MOV、AVI、M4V、FLV、WMV、MPEG、TS、OGV 和3GP；实际解码能力以 FFmpeg 为准。

## 读取范围和缓存

- 每次最多处理 600 秒，视频最长 120 分钟、单文件最多 256 MiB。下载优先选择 1080p，按画面短边处理横屏与竖屏；没有该档位时选择可用的较低档位，只有更高档位时选其中最低的档位。结果报告实际源文件尺寸，低于优先清晰度时提示。登录和权限可能影响可用档位，网页播放器的清晰度设置不控制本插件。
- 长视频按区间继续阅读，首次仍需下载完整文件；提高画质不会解除文件与缓存容量限制。复用已有低清缓存不会自动变成高清，需要从原视频链接重新开始下载。
- 整帧与局部画面的长边最多 1920 像素，保留普通横屏或竖屏 1080p 的尺寸，不放大小尺寸视频。局部补看从原视频裁剪，保留原始像素细节；结果中的 `frame_view` 及图片文字说明区分整帧和裁剪画面。
- 默认最多12个采样位置，可设为2–24个；极短片段会减少区间数。`balanced` 按变化密度分配，`uniform` 等距采样。分镜每页返回一张拼图，独立画面每次最多四张。只合并字节完全相同的图片，保留所有观察时间戳。
- 用 `watch:<job_id>` 复用原文件，选择新范围或具体时间戳。结果始终报告实际处理区间、采样时间、最大观察间隔和字幕来源；下载到预览或短文件时会提示。
- 同一服务串行处理视频，最多四个未完成任务。下载/抽帧/转写有超时、容量限制与取消。服务重启后将未完成任务标为中断，不自动重放。
- 缓存上限 2 GiB，最多 64 个任务。任务及导入文件保留约 24 小时，在服务启动或队列空闲时的新请求触发清理；达到限额时拒绝新任务。
- 数据按实例隔离。任务标识是不可猜测的读取凭证，无任务列表接口。MCP 当前未向本服务传递经过验证的聊天身份，因此这些标识不能作为严格的跨聊天身份隔离；Skill 要求只在原任务内使用它们。

## 开发验证

在具备 requirements-media.txt 依赖的 Python 环境中，于插件仓库运行 `npm run test:watch`。测试覆盖输入、B站兼容分支、字幕、时间覆盖、分页、取消、缓存复用、重启和 PCM 读取；有 FFmpeg 时还会生成短视频验证真实抽帧、1080p 整帧和从4K原视频裁剪细线，通过 stdio 协议读取原生图片。分镜测试还覆盖快切密度、字幕节选截断、清晰帧选择、变帧率时间戳、竖屏边缘保留、静态去重后的时间索引、跨任务与重启后的按格补看，以及采样失败与取消。下载格式测试使用 yt-dlp 的真实选择逻辑但不联网。PCM 数值测试另需 NumPy。

`node tests/watch-native.cjs` 验证独立 VM 中的通用附件入口、分块、签名链接、本地配置与错误传播。`node tests/watch-host.cjs <OpenBot源码目录>` 额外使用宿主实际的包解析器、MCP 客户端和图片转发逻辑，验证附件与本地文件经过新入口得到真实图片。这个路径仅用于开发验证，插件运行不依赖源码目录。

源码可直接导入开发版 OpenBot。正式市场目录固定到 Git 提交，需完成发布流程后再生成 catalog。上游参考与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
